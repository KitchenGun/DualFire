## 1. 개요

본 문서는 **동적 캠페인 시스템**의 세부 설계를 정의한다. 에이스 컴뱃 X를 레퍼런스로 하여, 일직선 스토리가 아닌 미션 간 인과관계가 존재하는 비선형 캠페인 구조를 구현한다.

본 게임은 **즉시 리플레이 방식**을 채택하며, 회차 개념을 두지 않는다. 데이터 구조의 세부 설계는 시나리오 확정 및 미션 수 결정 후 구체화한다.

---

## 2. 캠페인 흐름 구조

### 2.1 캠페인 규모 (시나리오 기획 결정 사항)

| 항목 | 내용 |
|------|------|
| 기본 루트 미션 수 | 10개 |
| 막 구조 | 3-4-3 (1막 3미션, 2막 4미션, 3막 3미션) |
| 분기 미션 비율 (목표) | 미션 번호의 60~70%에 분기 변형 |
| 총 콘텐츠 미션 수 | 분기 포함 14~17개 정도 |

세부는 시나리오기획 문서 참고.

### 2.2 기본 루트

캠페인은 **기본 루트**가 존재한다. 미션 1 → 2 → 3 → ... 순서로 이어지는 메인 경로이며, 처음 플레이하는 플레이어는 이 기본 루트를 따라 캠페인을 진행한다.

### 2.3 분기 미션

각 미션에서 **특정 조건을 달성**하면 분기 미션이 열린다. 예를 들어 미션 2에서 특정 조건을 충족하면 미션 2-1이 해금되어 플레이 가능해진다.

### 2.4 미션 잠금 없음

분기 미션이 열려도 **기존 미션이 잠기지 않는다.** 플레이어는 기본 루트와 분기 미션을 자유롭게 선택하여 플레이할 수 있다. 이미 클리어한 미션도 리플레이 가능하며, 리플레이를 통해 분기 조건을 달성할 수 있다.

### 2.5 자연스러운 리플레이 유도

이 구조에 의해:
- **1회차:** 기본 루트를 따라 캠페인을 진행하며 게임을 학습
- **리플레이:** 각 미션의 분기 조건을 탐색하고 달성하여 분기 미션을 해금
- **분기 미션:** 기본 루트와 다른 스테이지 구성, 스토리, 적 구성을 경험

## 3. 즉시 리플레이 방식

### 3.1 진행 방식 결정

본 게임은 **즉시 리플레이 방식**을 채택한다. 회차 개념을 두지 않는다.

### 3.2 즉시 리플레이의 동작

- 미션 클리어 시 다음 미션 해금
- 클리어된 미션은 캠페인 맵에 "클리어됨" 상태로 표시되며 자유롭게 리플레이 가능
- 분기 미션 해금 시 캠페인 맵에 새 노드 추가, 자유 플레이 가능
- 모든 기본 루트 미션 클리어 시 분기 누적에 따라 엔딩 미션 해금
- 엔딩 도달 후에도 같은 세이브에서 모든 미션과 분기 탐색 지속 가능

### 3.3 즉시 리플레이를 채택한 이유

이 게임의 다른 시스템들이 모두 즉시 리플레이를 전제로 설계되어 있다.

- 빌드 다양성 시스템(기체/로드아웃/슬롯 시너지)을 같은 미션에서 반복 실험 가능
- 도전과제 누적 조건 달성에 적합
- Hard 이상 난이도의 적 구성 변화를 학습하려면 반복 플레이 필요
- 동적 캠페인 분기 탐색을 캠페인 재시작 없이 자유롭게 시도 가능

본 게임은 미니멀 시나리오 노선이므로 회차 단위 방식의 장점(이야기 몰입)을 살릴 필요가 적다.

### 3.4 회차 시스템 미채용

**캠페인 1회 클리어 후 2회차 같은 회차 시스템은 도입하지 않는다.** 즉시 리플레이 방식이 본 게임의 진행 모델이며, 다회차 보상은 도전과제 해금 = 게임 전체 공유 정책으로 일부 대체된다.

## 4. 미션 간 인과관계

### 4.1 기본 원리

플레이어의 미션 결과가 이후 미션에 영향을 미친다. 이 영향은 **맵 구조 자체를 변경하는 것이 아니라**, 변화된 스테이지를 별도 스테이지 데이터로 관리하는 방식으로 구현한다.

### 4.2 영향의 표현

미션 간 인과관계는 다음 방식으로 표현된다.

| 표현 방식 | 설명 | 예시 |
|-----------|------|------|
| 스테이지 치환 | 조건 충족 시 해당 미션의 스테이지가 변화 버전으로 교체 | 미션 2 클리어 → 미션 4가 4-1로 치환 |
| 분기 미션 해금 | 조건 충족 시 새로운 미션이 캠페인 맵에 출현 | 미션 3에서 조건 달성 → 미션 3-1 해금 |
| 브리핑 변경 | 연동 미션 클리어 시 브리핑 메시지 변화 | 미션 브리핑 시스템 연동 |
| 엔딩 분기 | 누적 선택에 따라 엔딩 미션이 결정 | 7절 참고 |

### 4.3 분기 조건의 다중성

분기 미션 해금이나 스테이지 치환의 분기 조건은 **모든 조건이 충족되어야** 발동한다 (AND 로직).

- 일부 조건만 충족되는 경우는 분기 미발동 (= 기본 메시지/스테이지 유지)
- OR 로직(여러 조건 중 하나만 충족)은 채택하지 않음
- 단일 조건의 단순한 사례부터 다중 조건의 복합 사례까지 데이터로 표현 가능

이 정책은 미션 브리핑 시스템 v0.2의 분기 조건 처리와 일관된다.

## 5. 분기 조건

### 5.1 다양한 분기 조건 지원

분기 조건은 단순 클리어/미클리어 외에 다양한 조건을 지원한다.

| 조건 유형 | 예시 |
|-----------|------|
| 미션 클리어 | 해당 미션을 클리어 |
| 특정 랭크 이상 클리어 | "미션 3을 종합 A랭크 이상으로 클리어" |
| 보스 제한 시간 격파 | "보스를 N초 이내에 격파" |
| 보스 파츠 전파괴 | "보스의 모든 파츠를 파괴하고 클리어" |
| 특정 격파율 달성 | "공중 격파율 90% 이상" |
| 슈퍼웨폰 미사용 클리어 | "슈퍼웨폰을 사용하지 않고 클리어" |
| 노데스 클리어 | "사망 없이 클리어" |

### 5.2 조건의 설계 원칙

- 분기 조건은 플레이어의 **숙련도에 따라 자연스럽게 달성**될 수 있는 수준과 **의도적으로 도전해야 하는** 수준이 혼합되어야 한다.
- 특정 빌드를 강제하는 조건은 지양한다.
- 조건 달성 여부는 미션 클리어 시점에 판정하며, 클리어 평가 데이터를 활용한다.

### 5.3 분기 조건의 비표시

분기 조건은 **플레이어에게 표시하지 않는다.** 어떤 조건을 달성해야 분기가 열리는지는 플레이어가 직접 시도하면서 발견해야 한다.

이는 다음을 위함이다.
- 발견의 재미: "이 조건을 달성하면 무언가 변할까?"라는 탐색 동기 제공
- 자연스러운 리플레이 유도: 다양한 시도를 통해 우연히 분기를 발견하는 경험

## 6. 미션 간 인과관계 (방향성)

### 6.1 현 단계의 범위

데이터 구조의 세부 설계는 시나리오 확정 및 전체 미션 수 결정 후 구체화한다. 본 문서에서는 시스템이 지원해야 할 데이터의 방향성을 정의한다.

### 6.2 필요 데이터 요소

시스템이 관리해야 할 데이터 요소:

| 요소 | 설명 |
|------|------|
| 미션 목록 | 캠페인에 포함된 모든 미션 (기본 루트 + 분기 미션) |
| 미션 간 연결 관계 | 어떤 미션 다음에 어떤 미션이 올 수 있는지 |
| 분기 조건 | 분기 미션 해금 또는 스테이지 치환을 위한 조건 (AND 다중 조건 가능) |
| 미션별 스테이지 매핑 | 미션 ID → 스테이지 ID 매핑 (조건+난이도 조합에 따라 다른 스테이지로 치환) |
| 플레이어 진행 상태 | 각 미션의 클리어 여부, 분기 조건 달성 여부, 해금된 분기 미션 목록 |
| 엔딩 조건 | 캠페인 종료 시점의 분기 판정 데이터 |

### 6.3 스테이지 치환 로직 (난이도 통합)

게임이 미션을 로드할 때 다음 순서로 스테이지 ID를 결정한다.

1. 미션 ID 확인
2. 현재 난이도 확인
3. 동적 캠페인 분기 조건 충족 여부 확인
4. 위 조건 조합에 대응하는 스테이지 ID로 로드

플레이어에게는 동일한 미션으로 보이지만 내부적으로는 조건에 따라 다른 스테이지 데이터가 사용된다.

이 메커니즘은 동적 캠페인의 분기와 난이도 시스템의 차등이 동일한 "스테이지 치환" 로직으로 처리되어 시스템 일관성을 유지한다 (스테이지 구조 시스템 v0.2 7절 참고).

### 6.4 다단 분기 가능성

시스템은 다단 분기(예: 2-1 미션이 추가 분기로 2-1-1을 가짐)를 **시스템적으로 지원**하지만, **1편 컨텐츠에서는 단일 분기(2-1까지)에서 멈춘다.**

다단 분기 미사용 사유:
- 미션 수가 폭증하는 위험
- 시나리오 작업량이 기하급수적으로 증가
- 1편의 적정 규모를 넘어섬

시스템적으로는 차단하지 않아 차후 확장(예: DLC, 후속작) 시 활용 가능하다.

## 7. 캠페인 맵 UI

### 7.1 노드 그래프 형태

캠페인 맵은 **노드 그래프 형태**로 표시한다. 각 미션이 노드로 표현되며, 미션 간 연결이 선으로 표시된다.

### 7.2 그래프 형태의 결정

구체적인 그래프 형태(트리 구조 / 자유 그래프)는 UI 기획 단계에서 결정한다. 두 가지 가능성이 있다.

| 형태 | 특징 |
|------|------|
| 트리 구조 | 단순하고 직관적. 분기 구조가 명확히 보임. 아트 공수 낮음. |
| 자유 그래프 | 에이스 컴뱃 X처럼 지도 위에 미션 노드 배치. 시각적 연출 강함. 아트 공수 높음. |

### 7.3 노드 그래프를 채택한 이유

- 맵 형태(월드맵 등) 대비 아트 공수가 낮을 수 있다.
- 미션 간 연결 관계와 분기 구조가 직관적으로 보인다.
- 분기 미션이 해금되면 새 노드가 추가되어 시각적으로 확장감을 준다.

### 7.4 노드 상태 표시

| 상태 | 표시 |
|------|------|
| 미해금 | 비표시 또는 잠김 표시 |
| 해금됨 (미클리어) | 선택 가능 상태 |
| 클리어됨 | 클리어 표시 + 최고 랭크 표시 |
| 분기 미션 (해금됨) | 기본 루트와 구분되는 시각적 표시 |

분기 조건은 노드에 표시되지 않는다 (5.3절 참고).

### 7.5 분기 미션 해금 알림

분기 미션이 해금된 시점에 다음 두 가지 방식으로 플레이어에게 전달한다.

| 방식 | 설명 |
|------|------|
| 미션 클리어 직후 알림 | 클리어 평가 결과 화면에서 "새 미션 해금" 메시지 표시 |
| 캠페인 맵 시각 표현 | 새로 해금된 미션 노드를 강조 표시 (애니메이션, 아이콘, 색상 강조 등) |

이를 통해 플레이어가 "내 행동의 결과로 새로운 컨텐츠가 열렸다"는 즉각적 피드백을 받는다.

## 8. 엔딩 분기

### 8.1 엔딩 결정 구조

엔딩은 캠페인 진행 중 **어떤 분기 미션을 클리어했는가의 누적**에 의해 결정된다. 엔딩 직전 시점에서 플레이어의 분기 미션 클리어 상태를 확인하고, 이에 따라 엔딩 미션이 선택된다.

### 8.2 엔딩 미션 치환

엔딩 분기는 기존 스테이지 치환 구조와 동일하게 동작한다. 조건에 따라 다른 엔딩 미션(= 다른 스테이지)이 로드되며, 각 엔딩 미션은 독립적인 스테이지 데이터를 가진다.

### 8.3 엔딩 도달 후의 흐름

엔딩 미션 클리어 후 캠페인이 "엔딩 도달" 상태가 되지만, **종료되지 않는다.**

| 항목 | 처리 |
|------|------|
| 엔딩 도달 표시 | 캠페인 맵에 엔딩 도달 기록 |
| 미션 접근 | 모든 미션과 분기 탐색 지속 가능 |
| 다른 엔딩 도달 | 다른 분기 선택을 통해 다른 엔딩 도달 가능 |
| 도전과제 달성 | 엔딩 도달 후에도 도전과제 진행 가능 |

같은 세이브 데이터에서 다양한 엔딩과 분기를 모두 탐색할 수 있다.

### 8.4 엔딩 수

구체적인 엔딩 수와 분기 조건은 시나리오 기획에서 결정한다. 기본 방향은 다중 엔딩 (정확한 수는 미정).

## 9. 시스템 간 연동 지점

| 연동 시스템 | 연동 내용 |
|-------------|-----------|
| 스테이지 구조 | 조건+난이도에 따른 스테이지 치환 (별도 스테이지 데이터). 동일 메커니즘 사용. |
| 미션 브리핑 시스템 | 연동 미션 클리어 시 브리핑 메시지 변경 (분기 조건 다중성과 일관) |
| 클리어 평가 시스템 | 분기 조건 판정에 평가 데이터 활용 |
| 장비 해금 시스템 | 엔딩 도달 등 캠페인 진행 관련 도전과제 |
| 난이도 시스템 | 난이도 차등 + 동적 캠페인 분기가 동일 스테이지 치환 메커니즘으로 통합 |

## 11. 확정 사항 요약

| 항목 | 결정 사항 |
|------|-----------|
| 캠페인 구조 | 기본 루트 + 분기 미션 (10미션 3-4-3 구조) |
| 진행 방식 | 즉시 리플레이 방식 |
| 회차 시스템 | 미채용 |
| 미션 잠금 | 없음. 자유 선택. 리플레이 가능. |
| 미션 간 영향 | 스테이지 치환, 분기 미션 해금, 브리핑 변경, 엔딩 분기 |
| 분기 조건 다중성 | AND 로직 (모든 조건 충족 시 발동). OR 미사용. |
| 분기 조건 표시 | 비표시 (발견의 재미) |
| 다단 분기 | 시스템 지원, 1편 미사용 |
| 스테이지 치환 메커니즘 | 동적 캠페인 + 난이도 통합 (단일 메커니즘) |
| 엔딩 분기 | 분기 미션 클리어 누적에 따라 엔딩 미션 결정 |
| 엔딩 도달 후 | 같은 세이브에서 계속 플레이 가능 |
| 캠페인 맵 UI | 노드 그래프 (트리/자유 그래프, UI 기획에서 결정) |
| 분기 미션 해금 알림 | 클리어 직후 알림 + 캠페인 맵 시각 표현 |
| 데이터 구조 세부 | 시나리오 확정 후 구체화 |
