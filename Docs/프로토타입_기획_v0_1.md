## 0. 문서 운영 원칙

본 문서는 슈팅게임 기획서 v0.6의 P0 코어 시스템 4종을 프로토타입 단계에서 구현하기 위한 **기획 사양 문서**다. 어떤 시스템이 어떤 책임을 지고, 어떤 규칙으로 동작하는지를 기획 관점에서 정의한다.

상위 기획 문서는 시스템 로직과 의도를 정의하며, 본 문서는 그것의 프로토타입 단계 적용 범위를 정의한다. 본 문서와 상위 문서가 충돌할 경우 상위 문서가 우선하며, 본 문서의 해당 부분을 갱신한다.

수치/데이터 항목은 다음 두 마커로 구분 표기한다.

- **[제안]** — 구현 시작점으로 사용할 값. 검증 후 조정 가능.
- **[검증]** — 본 프로토타입의 핵심 결정 대상. 플레이 결과로 확정.

검증 단계 명칭은 다음과 같이 사용한다. 본 문서의 버전 번호와는 무관한 개념이다.

- **본 단계 (초기 검증):** 본 문서가 정의하는 현재 프로토타입 구현 단계.
- **후속 검증 단계:** 본 단계 종료 후 진행되는 추가 검증 단계. P1 진입 전에 회복 아이템 등 일부 항목을 추가 검증한다.

### 0.1 프로토타입 예외 정책

본 문서의 비목표(§1.3) 및 스텁 처리 항목(§2.2)은 프로토타입 검증을 위한 **의도적 축소**로 간주한다. 해당 항목들은 상위 문서의 최종 사양을 폐기하거나 변경하는 것이 아니라, 프로토타입 구현 범위에서만 임시 대체한다.

이 정책에 따라 다음 항목들은 "충돌"이 아닌 "의도된 임시 처리"이다.

- 슈퍼웨폰 슬롯은 정의하지만 효과는 미구현
- 기체 시스템은 스텁 1대만 사용
- 클리어 평가는 검증 리포트(§8.3)로 대체
- 회복 아이템은 디버그 키 또는 후속 검증 단계의 고정 위치 아이템으로 대체
- 보스는 엘리트 1체로 대체
- 멈춤 트리거 시스템은 엘리트 전투 상태(§5.5)로 간이 대체

P1 이후 단계에서 본 문서의 임시 처리가 상위 문서의 정식 사양으로 교체된다.

## 1. 프로토타입 목표

### 1.1 검증 가설

기획서 5.2절에 따라 본 프로토타입은 다음 4가지 가설을 검증한다.

| 가설 | 측정 방식 |
|------|----------|
| 지상/공중 판정 분리의 시각적 식별성 | 첫 등장 시 1초 이내에 적의 속성을 판별 가능한가 |
| 로드아웃 빌드 선택의 의미 | 다른 빌드로 같은 스테이지 플레이 시 체감 차이가 있는가 |
| 피탄 허용형 생존감 | 보호막 관리가 의식적인 자원 판단으로 작동하는가 |
| 기본 조작감 | 8방향 이동·저속 모드·사격이 슈팅게임 표준 수준인가 |

### 1.2 성공 기준

- 모든 P0 시스템이 데이터 기반으로 동작한다. 스테이지 웨이브 포함.
- 빌드 변경 시 같은 스테이지의 플레이 양상이 명확히 달라진다.
- 보호막 → 체력 → 사망 → 리스폰 → 미션 실패 흐름이 끊김 없이 동작한다.
- 이동/사격 입력은 버퍼링 없이 다음 게임 로직 프레임에 반영된다.
- 시각 반응은 60FPS 기준 4프레임 이내에 발생한다.

### 1.3 비목표

P1 이후 단계로 미루며 본 프로토타입에서 다루지 않는다. (§0.1 예외 정책 참고)

- 기체 시스템 완전 구현 (스텁 1대만 사용)
- 슈퍼웨폰 시스템 (슬롯만 존재, 효과 미구현)
- 보스 페이즈 시스템 (엘리트로 대체)
- 미션 브리핑, 클리어 평가, 동적 캠페인, 난이도, 도전과제, 해금
- 슬롯 시너지, 드론
- 스코어링 (격파 카운터까지만)
- 회복 아이템 시스템 정식 구현 (본 단계는 디버그 키, 후속 검증 단계에서 고정 위치 아이템)
- UI 폴리싱, 사운드/이펙트 폴리싱

## 4. 핵심 데이터 분류

본 단계에서 사용하는 주요 데이터의 항목 구성을 기획 관점에서 정리한다. 모든 항목은 데이터 테이블로 관리되며, CSV 임포트를 우선한다.

### 4.1 속성

게임 내 모든 적과 무장은 다음 두 속성을 기준으로 분류된다.

- **지상 속성** — 지상에 있는 적
- **공중 속성** — 공중에 있는 적
- **양면 속성** — 지상과 공중 양쪽에 동시에 해당하는 적 (양면 잡몹, 엘리트, 보스 등)

플레이어 본체는 속성이 없다. 적과 탄환만 속성을 가진다.

무장과 탄환은 속성을 **복수로 가질 수 있다**. 예를 들어 범용 무장은 지상과 공중 양쪽 속성을 동시에 보유한다. 적은 단일 속성 또는 양면이다.

**판정 규칙:** 탄환이 적에 부딪쳤을 때, 탄환의 속성 중 하나라도 적의 속성과 일치하면 데미지가 적용된다. 일치하지 않으면 데미지가 무시되고 탄환은 그대로 진행한다 (§5.1 참고).

### 4.2 무장

기본 무기와 특수 무장은 동일한 항목 구성을 공유한다. 슬롯 분류만 다르게 표기한다.

| 항목 | 설명 |
|------|------|
| 명칭 | UI 표시 이름 |
| 분류 | 기본 무기 / 특수 무장 |
| 속성 | 지상 / 공중 / 양쪽 |
| 발당 데미지 | 탄환 1발의 데미지 (최소 1) |
| 발사 속도 | 초당 발사 수 (0보다 커야 함) |
| 탄속 | 탄환 이동 속도 |
| 명중 처리 | 소멸 / 관통 / 제한 관통 |
| 제한 관통 횟수 | 제한 관통일 때만 사용 |
| 발사 위치 오프셋 | 기체 기준 탄환 발사 지점 |
| 탄환 비주얼 | 외형 |
| 탄환 색상 | 속성 식별용 색상 (검증 항목) |

### 4.9 등장 앵커

적의 등장 위치는 화면 기준 9개의 앵커로 지정한다. **앵커는 화면 경계가 아니라, 화면 안쪽 여백을 둔 진입 기준점**이다. 적이 화면 경계에서 갑자기 나타나기보다 안쪽에서 자연스럽게 등장하도록 의도된 위치이다.

| 앵커 | 위치 |
|------|------|
| 상단 좌측 | 화면 상단의 왼쪽 진입 위치 |
| 상단 중앙 | 화면 상단 중앙 |
| 상단 우측 | 화면 상단의 오른쪽 진입 위치 |
| 좌측 | 화면 중단 왼쪽 |
| 중앙 | 화면 중앙 (엘리트 등장 위치) |
| 우측 | 화면 중단 오른쪽 |
| 하단 좌측 | (보조) |
| 하단 중앙 | (보조) |
| 하단 우측 | (보조) |

정밀 위치 조정이 필요한 경우 위치 오프셋으로 미세 조정한다.

## 5. 시스템별 사양

### 5.1 지상/공중 판정 분리

#### 5.1.1 책임 범위

- 탄환이 적에 부딪쳤을 때 속성을 비교한다.
- 일치할 경우: 데미지를 적용하고 명중 이펙트를 재생한다. 이후 탄환의 명중 처리(소멸/관통/제한관통)에 따라 진행한다.
- 일치하지 않을 경우: 데미지를 무시하고 명중 이펙트도 재생하지 않는다. 탄환은 그대로 진행한다.
- 본 시스템은 플레이어 → 적 방향에만 적용된다. 적이 플레이어를 공격할 때는 속성 시스템이 작동하지 않는다.

#### 5.1.2 시각 식별성 — 핵심 검증 항목

상위 기획서 7장의 "시각적 식별 레이어 세부 적용"이 본 프로토타입의 핵심 결정 사항이다. 다음 4가지 후보를 모두 구현하고 디버그 토글로 비교한다.

| 후보 | 구현 방향 |
|------|----------|
| 색상 단독 | 지상 = 주황 계열, 공중 = 시안 계열 |
| 색상 + 형상 | 지상 = 각진 모델, 공중 = 둥근 모델 |
| 색상 + 형상 + 그림자 | 위에 더해 공중 적은 화면 바닥에 그림자 데칼 |
| 색상 + 형상 + 위치 레이어 | 공중 적은 시각적으로 더 위쪽에 표시 |

**[검증]** 새 플레이어가 가장 빠르고 정확하게 식별하는 조합을 결정한다. 측정은 "첫 등장 후 적의 속성을 판별하는 데 걸린 시간"으로 한다.

#### 5.1.3 보스/엘리트 처리

본 단계의 엘리트는 단일 판정 + 양면 속성으로 처리한다. 보스의 파츠 단위 콜리전, 파츠별 속성 분리 등은 P1 이후 도입한다.

### 5.2 플레이어 기동

#### 5.2.1 입력 매핑

| 액션 | 키보드 (기본) | 게임패드 |
|------|---------------|----------|
| 이동 | WASD / 화살표 | 좌측 스틱 |
| 저속 모드 (홀드 또는 토글) | Shift | LB |
| 기본 무기 사격 | Z / Space | A |
| 특수 무장 사격 | X | B |
| 슈퍼웨폰 발동 | C | Y |
| 일시정지 | Esc | Start |
| 로드아웃 핫스왑 (디버그) | 숫자 1~3 | — |

특수 무장 키는 단일 키이며, 장착된 특수 무장 2개가 같은 키로 발사된다 (§5.2.5 참고).

**[제안]** 게임패드 데드존 0.2 (옵션 조정 가능)
**[제안]** 저속 모드는 기본 홀드 (옵션에서 토글로 전환 가능)

#### 5.2.2 이동 처리

- 8방향 입력. 대각선은 자동 보정으로 같은 이동 속도를 유지한다.
- 가속/감속 곡선 없음. 입력 즉시 최대 속도, 떼는 즉시 정지.
- 화면 경계 클램프. 경계 밖으로 입력해도 위치는 경계에 고정된다.

**[제안]** 통상 이동 속도 = 화면 너비 대비 약 0.5초에 절반 이동 정도의 감각 (구체 값은 후술)
**[제안]** 통상 이동 속도 800 cm/s, 저속 모드 비율 0.5 (저속 시 400 cm/s)

**[검증]**
- 통상 이동 속도 600 / 800 / 1000 cm/s 중 최적
- 저속 모드 비율 0.4 / 0.5 / 0.6 중 최적

#### 5.2.3 저속 모드

- 진입: 홀드 (옵션에서 토글로 변경 가능)
- 시각 피드백: 엔진 글로우 색조 변화 또는 트레일 변경
- **히트박스는 표시하지 않는다.** 피탄 허용형 설계와의 일관성을 위해 의도적으로 노출하지 않는다.
- 모드 전환에 따른 히트박스 크기 변화는 없다.

#### 5.2.4 히트박스

- **[제안]** 반지름 30cm (기체 모델 폭의 약 35%)
- 디버그 모드에서 시각화 토글 가능. 정식 빌드에서는 비표시.

**[검증]**
- 크기: 25 / 30 / 35cm 중 최적
- 형상: 원형 / 캡슐 중 최적

#### 5.2.5 발사 규칙

본 단계의 발사 규칙은 다음 원칙을 따른다.

| 항목 | 규칙 |
|------|------|
| 기본 무기 사격 | 버튼 홀드 시 자동 연사. 기본 무기 1종 발사. |
| 특수 무장 사격 | 버튼 홀드 시 **장착된 특수 무장 2개가 각각 자동 발사**한다. |
| 쿨타임 | 각 무장은 자기 발사 속도에 따른 **개별 쿨타임**을 가진다. |
| 동시성 | 기본 무기와 특수 무장은 동시에 발사 가능하다. |
| 특수 1 / 특수 2 | 쿨타임을 공유하지 않는다. 각자 발사 가능 상태일 때 발사된다. |

**발사 속도 유효성:** 무장의 발사 속도는 0보다 커야 한다. 0 이하 값은 데이터 오류로 간주하고 해당 무장은 발사하지 않는다.

**의도:**
- 로드아웃 2슬롯의 의미를 살리되 입력 복잡도를 늘리지 않는다.
- 같은 무장을 양 슬롯에 넣으면 사실상 화력 2배 효과가 된다 (의도된 빌드 선택).
- 서로 다른 무장을 넣으면 두 발사 패턴이 자연스럽게 겹친다.

#### 5.2.6 특수 기동

별도 시스템 없음. 회피 기동·블링크 등의 특수 기동은 상위 문서에서 슈퍼웨폰 효과로 흡수되어 있으며, 본 단계에서는 미구현이다.

### 5.3 생존

#### 5.3.1 자원 구성

- **체력** — 기체에서 결정 (스텁: 5)
- **보호막 잔량** — 보호막 장비에서 결정 (스텁: 2 또는 4)
- **잔기** — 매 미션 시작 시 1기 (예비기)

#### 5.3.2 피격 처리 (핵심 규칙)

피격 시 다음 순서로 처리된다.

1. **무적 상태이면 무시.** 데미지 적용 없음.
2. **보호막 잔량이 1 이상이면:** 보호막을 데미지만큼 감소시킨다. 보호막이 0이 되면 파괴 처리(§5.3.3)를 진행한다. **이 경우 체력은 변화 없고, 피격 후 무적도 발동하지 않는다.**
3. **보호막이 0인 상태에서 피격되면:** 체력에 데미지를 적용하고, 피격 후 무적을 발동한다. 체력이 0 이하가 되면 사망 처리(§5.3.5)를 진행한다.

**핵심 규칙 두 가지:**

1. **보호막은 데미지만큼 감소한다.** 1 데미지면 1, 3 데미지면 3만큼 감소. 보호막 최대 잔량의 차이가 의미를 갖는다.
2. **데미지가 잔량보다 커도 초과분은 체력으로 전달하지 않는다.** 보호막은 "최후의 방패"로 기능한다.

이 두 규칙의 조합으로 보호막의 두 차원(총량, 재생 속도)이 빌드 선택의 의미를 갖는다.

#### 5.3.3 보호막 파괴 처리

보호막 잔량이 0이 되는 순간 다음을 처리한다.

- 보호막 장비에 "파괴 시 무적 시간"이 설정되어 있으면, 해당 시간 동안 무적을 부여한다.
- 그 외 특수 효과(주변 데미지, 슈퍼웨폰 충전 등)는 P1 이후.

#### 5.3.4 보호막 자동 재생

- 보호막 잔량이 최대치 미만이면 자동으로 재생된다.
- 보호막 장비의 "재생 간격"마다 잔량이 1씩 회복된다.
- 재생은 무적 여부와 무관하게 진행된다.

#### 5.3.5 사망 / 잔기 / 리스폰

- 체력이 0 이하가 되면 사망 처리.
- 잔기가 남아 있으면: 잔기 1 차감, 체력과 보호막 풀 충전, 3초 무적 부여 후 리스폰.
- 잔기가 0이면: 미션 실패.

#### 5.3.6 무적 상태

본 단계에서 무적은 다음 세 가지 상황에서 발동한다.

- **피격 후 무적** — 체력 데미지를 받은 직후. **[검증]** 2.0 / 2.5 / 3.0초 중 최적
- **보호막 파괴 무적** — 보호막이 0이 된 직후 (보호막 장비 설정에 따름)
- **리스폰 무적** — 사망 후 부활 시 3초

**중요:** 새 무적이 발동되면 기존 잔여 시간과 신규 지속 시간 중 **더 긴 값**이 적용된다. 짧은 무적이 더 긴 무적을 덮어쓰는 버그를 방지하기 위한 정책이다.

**무적 중에는 공격·이동·회복이 모두 가능하다.** 피격만 무시된다.

#### 5.3.7 회복 (본 단계 단순화)

- 본 단계에서 회복 아이템 시스템은 미구현이다.
- 디버그 키로 체력/보호막 풀충전을 시뮬레이션한다.
- 보호막 자동 재생은 정상 동작한다.
- 후속 검증 단계에서 고정 위치 회복 아이템을 추가 검증한다 (§9.1 참고).

#### 5.3.8 저체력 경고

- 화면 가장자리 이펙트로 표현한다.
- **[제안]** 임계값 = 체력 1 이하 (최대 체력 5 기준)
- **[검증]** 임계값 1 이하 vs 2 이하

### 5.4 로드아웃

#### 5.4.1 책임

- 출격 전 기체와 4개 슬롯의 장비를 선택한다.
- 6개 슬롯(기체 + 기본 무기 + 특수 무장 2 + 슈퍼웨폰 + 보호막) 모두 채워졌는지 검증한다.
- 검증 통과 시 선택된 빌드로 미션을 시작한다.

#### 5.4.2 슬롯 구성

모든 기체 공통으로 다음 슬롯 구성을 가진다.

| 슬롯 | 수량 | 본 단계 처리 |
|------|------|--------------|
| 기체 | 1 | 스텁 1대 강제 |
| 기본 무기 | 1 | 3종 중 선택 |
| 특수 무장 | 2 | 4종 중 각 슬롯 자유 선택 (중복 가능) |
| 슈퍼웨폰 | 1 | 더미 1종 강제 |
| 보호막 | 1 | 2종 중 선택 |

#### 5.4.3 출격 검증

- 6개 슬롯 모두 비어있지 않을 때만 출격 허용.
- 빈 슬롯이 있으면 "비어있는 슬롯이 있습니다" 안내를 표시한다.

#### 5.4.4 빌드 적용 흐름

미션 시작 시 다음 순서로 선택된 빌드가 게임에 적용된다.

1. 기체에서 최대 체력, 외형, 히트박스 크기를 가져와 플레이어에 적용
2. 보호막 장비에서 최대 잔량, 재생 간격, 파괴 시 무적 시간을 가져와 적용
3. 기본 무기, 특수 무장 1, 특수 무장 2를 각 슬롯에 장착
4. 슈퍼웨폰은 더미이므로 슬롯에 등록만 (동작 없음)
5. 미션 진행 시작

#### 5.4.5 UI

본 단계의 로드아웃 UI는 디버그 수준이다.

- 각 슬롯마다 좌우 화살표 또는 드롭다운으로 장비를 순회한다.
- 출격 버튼과 빈 슬롯 안내 텍스트가 있다.
- 폴리싱은 본 단계의 목표가 아니다.

#### 5.4.6 프리셋

본 단계에서는 프리셋 저장/로드 기능이 없다. 현재 세션 중에만 단일 빌드가 메모리에 유지된다.

### 5.5 스테이지 컨트롤러

P0 시스템의 보조 구현이다. 정식 스테이지 구조 시스템의 완전 구현이 아닌, 검증을 위한 간이 버전이다.

#### 5.5.1 책임

- 자동 스크롤 진행
- 시간 기반 웨이브 트리거 (등록된 웨이브를 발생 시각에 맞춰 스폰)
- 엘리트 등장 시각에 도달하면 엘리트 전투 상태로 전환
- 엘리트 격파 또는 제한 시간 초과 시 미션 종료

#### 5.5.2 진행 상태

스테이지는 다음 3개 상태를 순서대로 거친다.

1. **타임라인** — 자동 스크롤과 웨이브 스폰이 진행되는 일반 상태
2. **엘리트 전투** — 엘리트 등장 후의 단일 보스전 상태
3. **종료** — 클리어 또는 실패 확정

상태 전환:

```
[타임라인]
   │
   │ 엘리트 등장 시각 도달
   ▼
[엘리트 전투]
   │
   ├── 엘리트 격파 ──→ [종료: 클리어]
   │
   └── 제한 시간 초과 ──→ [종료: 실패]
```

#### 5.5.3 엘리트 전투 상태 진입 시 처리

| 항목 | 처리 |
|------|------|
| 자동 스크롤 | 정지 |
| 후속 웨이브 스폰 | **중단** (남은 웨이브는 진행되지 않음) |
| 화면 위 기존 잡몹 | **유지**. 기존 이동 패턴 그대로 진행하다 화면 밖으로 나가면 제거. |
| 엘리트 스폰 | 화면 중앙 앵커에 1체 스폰 |
| 제한 시간 카운트다운 | 엘리트 격파 제한 시간 적용 시작 |

> 60~80초 구간에서 보호막 압박을 받은 상태가 엘리트 전투로 자연스럽게 이어지도록, 잡몹은 강제 제거하지 않는다. 단, 신규 잡몹은 더 이상 스폰되지 않으므로 시간이 지나면 잡몹이 자연 소거되어 엘리트 단일 전투로 수렴한다.

#### 5.5.4 미션 종료 조건

- **클리어:** 엘리트 격파 시점에 미션 클리어로 종료한다.
- **실패:** 엘리트 격파 제한 시간 초과, 또는 잔기 0 상태에서 사망 시 미션 실패로 종료한다.
- 두 경우 모두 §8.3 검증 리포트가 출력된다.

> **시간 경과만으로 미션 클리어되는 경로는 없다.** 엘리트 격파가 유일한 클리어 조건이다. 이는 빌드별 화력 차이를 측정하기 위한 의도적 설계이다.

## 6. 스텁 컨텐츠 정의

### 6.1 스텁 기체

| 항목 | 값 |
|------|-----|
| 명칭 | 프로토타입 기체 |
| 최대 체력 | 5 |
| 히트박스 반지름 | 30cm **[제안]** |
| 외형 | 임시 큐브 또는 단순 비행기 모델 |

### 6.2 스텁 무장

#### 6.5.1 적 공격 패턴 동작 명세

본 단계는 적 공격 패턴 시스템의 완전 구현이 아니므로, 다음 3개 패턴만 정의한다. 정식 패턴 시스템은 P1 이후.

**단발 조준**
- 발사 간격마다 1발 발사
- 발사 시점의 플레이어 현재 위치 방향으로 조준
- 적탄 1개

**3방 분산**
- 발사 간격마다 3발 동시 발사
- 중심 방향은 플레이어 현재 위치 방향
- 발사 각도는 중심 기준 -15° / 0° / +15°
- 적탄 3개, 동일 속도

**3방 회전**
- 발사 간격마다 3발 동시 발사
- 기준 각도 θ에서 θ / θ+120° / θ+240° 세 방향으로 발사
- 발사 후 기준 각도를 +30° 회전시켜 다음 사이클에 누적 적용
- **플레이어를 조준하지 않는다.** 회전 패턴 자체가 위협이다.

세 패턴 모두 적이 살아있는 동안 계속 반복된다.

**화면 밖 처리:** 적이 화면 밖 판정 영역을 벗어나면 **즉시 제거되며, 발사도 중단된다.** 유지 시간이나 페이드 처리는 본 단계에서 도입하지 않는다.

## 8. 검증 도구

### 8.1 디버그 HUD

플레이 중 화면에 다음 정보를 표시한다.

- 체력 / 보호막 잔량 (좌상단)
- 현재 로드아웃 슬롯 (우상단)
- 격파 카운터 (지상 / 공중 / 양면 분리 표시)
- 피탄 카운터 (보호막 흡수 / 체력 데미지 분리 표시)
- 무적 잔여 시간
- 스테이지 상태 + 엘리트 격파 제한 시간 카운트다운 (해당 상태일 때)
- FPS

### 8.2 치트키

| 키 | 효과 |
|---|------|
| F1 | 히트박스 시각화 토글 |
| F2 | FPS 표시 토글 |
| F3 | 적 속성 라벨 강제 표시 (시각 식별 검증용) |

### 8.3 미션 결과 검증 리포트

미션 종료 시(클리어 또는 실패) 화면에 다음 정보를 표시한다. 이는 정식 클리어 평가 시스템이 아닌, **빌드 검증용 리포트**이다.

**양면 적 격파율 집계 정책:**

양면 속성 적은 **공중 카운트와 지상 카운트 양쪽에 동시 포함**한다. 이는 상위 클리어 평가 시스템의 카운트 규칙과 정합되도록 한 것이다. 추가로 양면 적의 단독 카운트를 보조 항목으로 함께 표시하여, 양면 적 대응력을 별도로 확인할 수 있게 한다.

**리포트 항목:**

- 결과 — 클리어 / 실패
- 클리어 시간 — 미션 종료까지 경과 시간

- **로드아웃 (사용된 빌드)**
  - 기체
  - 기본 무기
  - 특수 무장 1
  - 특수 무장 2
  - 보호막

- **격파 (양면 적은 양쪽에 포함)**
  - 공중 적 격파 수 / 등장 수 / 격파율
  - 지상 적 격파 수 / 등장 수 / 격파율

- **보조 항목**
  - 양면 적 단독 격파 수 / 등장 수 / 격파율
  - 엘리트 격파 여부

- **피탄 통계**
  - 총 피탄 횟수
  - 보호막 흡수 횟수
  - 체력 데미지 횟수

- **사망 통계**
  - 사망 횟수

**예시:**

```
- 결과: 클리어
- 클리어 시간: 92.4초

- 로드아웃
  - 기체: 프로토타입 기체
  - 기본 무기: 대공 머신건
  - 특수 무장 1: 대공 미사일
  - 특수 무장 2: 폭격
  - 보호막: 경량 보호막

- 격파 (양면 적은 양쪽에 포함)
  - 공중 적: 17 / 20  (85.0%)
  - 지상 적:  8 / 14  (57.1%)

- 보조
  - 양면 적 단독:  3 /  4  (75.0%)
  - 엘리트 격파: 예

- 피탄
  - 총 피탄: 7회
  - 보호막 흡수: 5회
  - 체력 데미지: 2회

- 사망: 0회
```

위 예시에서 공중 적 분모 20 = 순수 공중 적 16 + 양면 적 4. 지상 적 분모 14 = 순수 지상 적 10 + 양면 적 4. 양면 적이 양쪽 분모/분자에 포함되며, 보조 항목에 단독 카운트가 별도로 표시된다.

엔진 콘솔 로그에 동일 정보를 출력하고, 누적 분석을 위해 CSV 행으로 기록한다.

### 8.4 로깅

다음 이벤트마다 로그를 기록한다.

- **격파 시:** 시각, 적 종류, 적 속성(공중/지상/양면), 사용 무장, 속성 일치 여부, 데미지
- **피격 시:** 시각, 들어온 데미지, 피격 전 보호막, 보호막 흡수량, 피격 전 체력, 피격 후 체력, 무적 여부
- **출격 시:** 시각, 전체 로드아웃 스냅샷
- **미션 종료 시:** 시각, 결과, 경과 시간, 엘리트 격파 여부, 속성별 격파 수

### 9.1 회복 아이템 후속 검증 계획

본 단계에서 회복 아이템은 디버그 키로 시뮬레이션한다. 보호막/체력 구조의 1차 검증이 완료된 후, **후속 검증 단계**에서 다음과 같이 회복 아이템 1차 검증을 추가한다.

| 항목 | 내용 |
|------|------|
| 형태 | 고정 위치 회복 아이템 1~2개 (스테이지 데이터에 좌표 명시) |
| 동작 | 플레이어 접촉 시 체력 우선 회복 → 만충 시 보호막 충전 |
| 시스템 | 정식 아이템 드롭 시스템은 미구현. 정해진 위치에 단순 스폰만. |
| 검증 목표 | 회복 타이밍 판단(지금 먹을까 vs 위험 회피)의 게임플레이 가치 |

정식 드롭 시스템(몬스터별 드롭 테이블, 튕김 이동, 체류/소멸 등)은 P1 이후.
