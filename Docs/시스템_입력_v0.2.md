# 입력 시스템 — 세부 기획

**문서 종류:** 시스템 세부 기획
**상위 문서:** 슈팅게임 기획서 v0.6
**관련 문서:** 코어시스템_플레이어기동_v0.2 (8장), 코어시스템_로드아웃_v0.4, 프로토타입_기획_v0_1 (5.2절)
**Version 0.2**
**2026.07.02**

---

## 1. 개요

본 문서는 플레이어 입력 시스템의 사양을 정의한다. 입력 장치, 입력 액션 목록과 키 매핑, 사격 입력 규칙, 매핑 컨텍스트 구조, 데드존/키 리바인딩 정책, 그리고 미구현 항목의 구현 로드맵을 다룬다.

입력 장치 우선순위와 자동 전환의 상위 규칙은 **코어시스템_플레이어기동_v0.2 8장**이 정의하며, 본 문서는 이를 구현 관점에서 구체화한다. 구현은 Unreal Engine 5의 **Enhanced Input** 시스템을 기반으로 한다.

---

## 2. 입력 장치

### 2.1 지원 장치

- **키보드:** 기본 지원
- **게임패드:** 기본 지원

두 장치 모두 기본 지원하며, 키 바인딩은 옵션에서 변경 가능하다 (7장 참고).

### 2.2 장치 우선순위 및 자동 전환

코어시스템_플레이어기동_v0.2 §8.2를 따른다.

| 상황 | 처리 |
|------|------|
| 게임 시작 시 | 게임패드를 우선 입력 장치로 인식 |
| 현재 사용 중인 장치에서 입력 | 정상 처리 |
| 다른 장치에서 입력 감지 | 자동 일시정지 + 인게임 메뉴 표시 |

**구현 위치 방침:** 장치 전환 감지는 일시정지 중에도 동작해야 하므로 Pawn이 아닌 **PlayerController 또는 LocalPlayer Subsystem 레벨**에 구현한다 (Phase B, 8장 참고).

## 3. 입력 액션 목록

### 3.1 구현 완료

| 액션 | 값 타입 | 키보드 | 게임패드 | 처리 |
|------|---------|--------|----------|------|
| IA_Move | Axis2D | 방향키(↑↓←→) | 좌측 스틱 (데드존 0.1) | 8방향 이동 |
| IA_FirePrimary | Boolean | Z, Space | A (FaceButton_Bottom) | 기본 무기 슬롯 발사 |
| IA_FireSpecial1 | Boolean | X | B (FaceButton_Right) | 특수무장 슬롯 1 발사 |
| IA_FireSpecial2 | Boolean | C | X (FaceButton_Left) | 특수무장 슬롯 2 발사 |

이동 키는 최초 WASD로 구현했으나, 방향키 조작으로 변경했다 (2026.07.02).

### 3.2 계획 (미구현)

| 액션 | 키보드 | 게임패드 | 도입 시점 |
|------|--------|----------|-----------|
| IA_SlowMode (저속 모드) | Shift | LB (LeftShoulder) | Phase A |
| IA_SuperWeapon (슈퍼웨폰 발동) | 미정 (Z/X/C 사용 중) | 미정 (A/B/X 사용 중, Y 후보) | Phase A — 발동 방식이 디자인에 따라 달라질 수 있어 키 배정은 슈퍼웨폰 시스템 착수 시 확정 |
| IA_Pause (일시정지) | Esc | Start | Phase B |
| 로드아웃 핫스왑 (디버그) | 숫자 1~3 | — | 필요 시 |

## 4. 사격 입력 규칙

### 4.1 슬롯 기준 3버튼 체계

사격 입력은 **로드아웃 슬롯 기준**으로 동작한다 (코어시스템_로드아웃_v0.4 §2.1의 슬롯 구조와 1:1 대응). 최초에는 특수무장 2슬롯을 버튼 하나로 묶어 동시 발사하는 2버튼 체계로 구현했으나, 기획 논의(2026.07.02) 결과 슬롯마다 독립된 버튼을 배정하는 3버튼 체계로 변경했다.

| 버튼 | 대상 슬롯 | 규칙 |
|------|-----------|------|
| 기본 무기 사격 (IA_FirePrimary) | 기본 무기 슬롯 | 버튼 홀드 시 자동 연사 |
| 특수무장 1 사격 (IA_FireSpecial1) | 특수무장 슬롯 1 | 버튼 홀드 시 자동 연사 |
| 특수무장 2 사격 (IA_FireSpecial2) | 특수무장 슬롯 2 | 버튼 홀드 시 자동 연사 |

슬롯에 어떤 속성(범용/대공/대지)의 무기를 장착했는지와 무관하게, 버튼은 슬롯만 바라본다. 이는 로드아웃 시스템의 "슬롯별 속성 자유 선택" 원칙과 정합한다. 3개 버튼은 서로 독립적으로 바인딩되어 있어 동시 입력(예: 기본무기+특수1+특수2 동시 홀드)도 가능하다 — 손이 꼬일 수 있다는 우려가 논의에서 제기되었으므로, 실제 플레이 테스트 후 필요 시 재검토한다.

### 4.2 쿨타임

- 각 무장은 자기 발사 속도(FireRate)에 따른 **개별 쿨타임**을 가진다.
- 세 슬롯(기본무기/특수1/특수2)은 서로 다른 버튼에 배정되어 있으므로 쿨타임뿐 아니라 입력 자체가 완전히 독립적이다.
- 세 버튼은 동시에 발사 가능하다.

### 4.3 발사 중인 무장의 시각적 식별

발사 로그(`LogDualFire`)는 콘솔에서만 보여 플레이 중 즉시 확인이 어렵다. `WeaponComponent::FireLoadoutSlot`에서 발사 성공 시 `GEngine->AddOnScreenDebugMessage`로 화면에도 동일 정보를 표시한다 (Development 빌드 한정, Shipping 제외).

- 슬롯별 고정 메시지 키를 사용해 연사 중에도 줄이 쌓이지 않고 갱신된다.
- 슬롯별 색상 구분: 기본무기=Cyan, 특수1=Yellow, 특수2=Orange.
- 표시 형식: `[슬롯 표시명] Fired 무기ID`, 표시 시간 1초.

### 4.4 발사 속도 유효성

무장의 발사 속도는 0보다 커야 한다. **0 이하 값은 데이터 오류로 간주하여 장착 시점에 거부**하며, 해당 무장은 발사되지 않는다. 거부 시 경고 로그로 데이터 오류를 노출한다.

### 4.5 발사 모드 (FireMode)

| 모드 | 상태 | 동작 |
|------|------|------|
| Auto | **확정 (기본값)** | 버튼 홀드 시 쿨타임 간격으로 자동 연사 |
| SingleShot | 예약 (미구현) | 클릭당 1발. 구현 전까지 Auto로 폴백하며 경고 로그 출력 |

무기 데이터(FWeaponRow)의 FireMode 필드는 발사 처리에서 분기되며, SingleShot은 코드에 분기 자리만 마련된 상태다. SingleShot 무기 데이터가 실제로 도입되는 시점에 구현한다.

## 5. 매핑 컨텍스트 구조

### 5.1 현재 구조

| 컨텍스트 | 우선순위 | 등록 시점 | 내용 |
|----------|----------|-----------|------|
| IMC_PlayerDefault | 1 | 플레이어 Pawn BeginPlay | 이동 + 사격 (게임플레이 전용) |

플레이어 리스폰은 동일 Pawn 재활성화 방식이므로 컨텍스트 중복 등록이 발생하지 않는다.

### 5.2 계획 구조 (Phase B)

| 컨텍스트 | 우선순위 | 활성 조건 | 내용 |
|----------|----------|-----------|------|
| IMC_System | 높음 | 항상 활성 | 일시정지 등 시스템 입력 |
| IMC_PlayerDefault | 중간 | 게임플레이 중 | 이동 + 사격 + 저속모드 + 슈퍼웨폰 |
| (UI 컨텍스트) | 최상위 | 메뉴 열림 시 | UI 탐색 (CommonUI 라우팅) |

일시정지는 게임플레이 컨텍스트가 아닌 항상 활성인 IMC_System에 배치한다. 메뉴 개폐에 따른 컨텍스트 추가/제거는 PlayerController의 push/pop 헬퍼로 일원화한다.

### 5.3 입력 액션 참조 관리 (Phase A)

현재 Pawn이 IMC와 IA를 개별 프로퍼티로 참조한다. 기체 시스템 도입으로 기체별 Pawn이 늘어나기 전에, IMC+IA를 묶은 **InputConfig 데이터 에셋**으로 통합하여 Pawn은 단일 참조만 가지도록 전환한다. 액션 미할당은 경고 로그로 노출한다 (구현 완료).

## 6. 데드존 정책

- **확정 방향:** 코어시스템_플레이어기동_v0.2 §8.3에 따라 **옵션에서 플레이어가 직접 조정 가능**하게 구현한다 (Phase C).
- **현재 상태 (임시):** 데드존 0.1이 IMC 에셋(좌측 스틱 매핑의 Dead Zone Modifier)에 고정되어 있으며 런타임 변경은 지원하지 않는다.
- **이관 계획:** 옵션 시스템 도입 시 UEnhancedInputUserSettings 기반으로 전환하고, 에셋의 정적 Modifier는 제거한다.

---

## 7. 키 리바인딩 정책

- **확정 방향:** 코어시스템_플레이어기동_v0.2 §8.1에 따라 키 바인딩은 옵션에서 변경 가능하게 구현한다.
- **기반 기술:** Enhanced Input의 Player Mappable Keys + UEnhancedInputUserSettings (데드존 옵션과 저장 체계 공유).
- **단계:** Phase A에서 신규+기존 매핑 전체에 Mappable Key Settings를 일괄 부여하고, Phase C에서 리바인딩 UI를 노출한다. 액션 수가 적은 지금 부여 방침을 확정해 소급 비용을 최소화한다.

## 8. 구현 로드맵

| Phase | 착수 시점 | 내용 |
|-------|-----------|------|
| A | 저속모드/슈퍼웨폰 기능 착수 시 | IA_SlowMode + IA_SuperWeapon 추가, InputConfig 데이터 에셋 도입, Mappable Key Settings 일괄 부여 |
| B | UI/일시정지 시스템 착수 시 | IMC_System 분리, PlayerController IMC push/pop 헬퍼, 입력 장치 자동 전환 감지 |
| C | 옵션 시스템 착수 시 | UEnhancedInputUserSettings 활성화 — 키 리바인딩 UI + 데드존 옵션 조정 |
| D | 연출 시스템 착수 시 | 사격 잠금 (WeaponComponent::SetFiringLocked, 이동 잠금과 동일 패턴) |

각 Phase는 해당 기능 착수 시 같은 작업 단위로 묶어 진행하며, 선제 구현하지 않는다.

## 9. 시스템 간 연동 지점

| 연동 시스템 | 연동 내용 |
|-------------|-----------|
| 플레이어 기동 시스템 | 이동/저속모드 입력 전달, 입력 장치 규칙(8장)의 상위 정의 |
| 로드아웃 시스템 | 사격 버튼과 슬롯 구조의 1:1 대응 |
| 슈퍼웨폰 시스템 | 발동 전용 키 (Phase A) |
| UI 시스템 | 일시정지 메뉴, 장치 전환 시 인게임 메뉴, CommonUI 입력 라우팅 |
| 옵션 시스템 | 키 리바인딩, 데드존 조정, 저속모드 홀드/토글 전환 |
