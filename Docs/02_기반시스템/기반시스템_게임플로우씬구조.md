## 1. 개요

본 문서는 게임 전체의 씬(화면) 구성과 전환 흐름, 씬 간에 전달·유지되는 상태를 정의한다. 기존 시스템 문서들에 분산되어 있던 플로우 정의(게임 플로우 시뮬레이션 11단계 검증 결과)를 구현 관점의 씬 구조로 통합 정리한 문서다.

각 씬의 내부 UI 구성은 UI 기획에서 다루며, 본 문서는 씬의 존재·역할·전환 규칙까지를 다룬다.

## 2. 씬 목록

| 씬 | 역할 |
|-----|------|
| 타이틀 | 게임 시작 진입점 |
| 세이브 슬롯 선택 | 5개 슬롯 중 선택 / 새 세이브 생성 / 삭제 |
| 캠페인 맵 (허브) | 미션 선택 + 메타 컨텐츠 진입 허브 |
| 미션 브리핑 | 미션 내용/목표/힌트 표시, 선택된 난이도 확인 (변경 불가 — 난이도 선택·변경은 캠페인 맵 전용) |
| 로드아웃 (격납고) | 기체/장비 선택, 프리셋, 시너지 표시, 출격 |
| 인게임 (스테이지) | 실제 플레이 |
| 클리어 평가 | 평가 결과/보상/알림 표시, 다음 행동 선택 |
| 실패 화면 (간이) | 실패 사유 표시, 즉시 리플레이 동선 |
| 옵션 | 설정 (어느 씬에서든 오버레이 접근) |

### 2.1 캠페인 맵의 허브 역할 — 확정

캠페인 맵을 메타 컨텐츠의 허브로 사용한다. 캠페인 맵에서 진입 가능한 하위 화면:

- 상점 (장비/기체 구매)
- 시너지 도감
- 도전과제 목록
- 기록실 (미션별 최고 기록 열람)
- 로드아웃 프리셋 관리 (출격과 무관하게 빌드를 미리 구성)

별도의 격납고 허브 씬을 두지 않고 캠페인 맵에 통합하는 이유: 씬 계층을 얕게 유지하여 "미션 선택 → 출격"의 메인 루프 동선을 짧게 만들기 위함. (Raptor의 격납고-메뉴 통합 구조와 유사한 접근)

## 3. 씬 전환 흐름

### 3.1 메인 루프

```
타이틀
  → 세이브 슬롯 선택
    → 캠페인 맵 (허브)
      → 미션 선택 + 난이도 선택
        → 미션 브리핑 (스킵 가능)
          → 로드아웃
            → 출격
              → 인게임 (스테이지)
                → 미션 클리어 → 클리어 평가
                  → "미션 선택으로" → 캠페인 맵
                  → "리플레이" → 미션 브리핑 (동일 미션·동일 난이도)
                → 미션 실패 → 실패 화면 (간이, 평가 미산출)
                  → "리플레이" → 미션 브리핑 (동일 미션·동일 난이도)
                  → "미션 선택으로" → 캠페인 맵
```

### 3.2 전환 규칙

- 브리핑 → 로드아웃: 브리핑에서 진행 시 로드아웃으로. 로드아웃에서 브리핑 정보 재확인 가능
- 로드아웃 → 출격: 로드아웃 시스템 7.3의 출격 검증 흐름(7단계) 수행 후 출격 확정
- 리플레이: 동일 미션 + 동일 난이도 + 동일 확정 스테이지로 브리핑부터 재진입 (정확한 재도전). 난이도 변경·최신 상태 재계산은 캠페인 맵을 통해서만
- 인게임 중도 이탈(포기): 미션 실패와 동일 처리 — 실패 화면 경유 (사유 표기: 중도 이탈)
- 뒤로 가기: 브리핑 ↔ 캠페인 맵, 로드아웃 ↔ 브리핑은 자유 왕복 가능. 출격 확정 후에는 불가

## 4. 출격 컨텍스트 (씬 간 전달 상태)

출격 확정 시 다음 상태가 하나의 컨텍스트로 묶여 인게임에 전달된다.

| 상태 | 결정 시점 |
|------|-----------|
| 미션 | 캠페인 맵에서 선택 |
| 난이도 | 캠페인 맵에서 선택·변경 (브리핑은 표시만) |
| 분기 충족 상태 | 세이브 데이터에서 자동 결정 (사용할 스테이지 결정에 관여) |
| 확정 스테이지 식별자 | **출격 준비 컨텍스트 생성 시(캠페인 맵에서 미션·난이도 선택) 결정** — 미션+난이도+분기 상태로부터 최종 스테이지를 1회 결정하여 고정. 브리핑·로드아웃이 이 식별자를 참조한다 (로드아웃의 환경 검증에 필요). 인게임은 이 식별자만 로드 (출격 후 세이브 상태 변화에 흔들리지 않음, 디버그·재현 용이) |
| 로드아웃 (기체 1 + 장비 슬롯 5칸: 기본 무기 1·특수무장 2·슈퍼웨폰 1·보호막 1) | 출격 버튼 승인 시 확정 (출격 준비 로드아웃의 커밋 — 로드아웃 시스템 4.1) |
| 활성화 시너지 | 로드아웃 조합에서 자동 결정 |

**컨텍스트의 2단계 구조 — 결정 시점의 분리:**

| 상태 | 결정 시점 |
|------|-----------|
| 미션·난이도 | 캠페인 맵에서 선택 |
| 분기 상태 스냅샷 | 출격 준비 컨텍스트 생성 시 |
| 확정 스테이지 식별자 | 출격 준비 컨텍스트 생성 시 |
| 로드아웃·활성 시너지 스냅샷 | 출격 버튼 승인 시 (최종 출격 컨텍스트 확정) |

캠페인 맵에서 미션·난이도를 선택하는 순간 **출격 준비 컨텍스트**(미션/난이도/분기 스냅샷/확정 스테이지)가 생성되고, 브리핑과 로드아웃 씬은 이를 참조한다 — 로드아웃 씬 진입 시점에 이미 확정 스테이지가 존재하므로 환경 검증이 가능하다 (결정 시점 순환 없음). 출격 버튼 승인 시 로드아웃·시너지 스냅샷이 더해져 **최종 출격 컨텍스트**로 확정된다.

인게임 종료 시 출격 컨텍스트와 플레이 결과는 **종료 결과에 대응하는 결과 화면**에 전달된다.

- 클리어 → 클리어 평가 화면
- 실패·중도 이탈 → 실패 화면

결과 화면에서 리플레이를 선택하면 **이전 출격 준비 컨텍스트(미션·난이도·분기 스냅샷·확정 스테이지)를 그대로 복사해 새 준비 컨텍스트를 생성**하고, 로드아웃은 다시 선택할 수 있다 — **방금 플레이한 동일 스테이지 변형을 정확히 재도전**한다 (빌드를 바꿔 같은 미션을 비교하는 재미 보장). 분기 스냅샷까지 복사하는 이유: 확정 스테이지는 같은데 브리핑만 최신 세이브 분기 상태로 바뀌면 설명과 실제 플레이가 불일치한다. 출격 직전에는 로드아웃과 활성 시너지만 새로 확정한다. 캠페인 맵을 경유해 다시 출격하면 최신 캠페인 상태로 전부 재계산한다. **캠페인 맵 복귀 또는 새 출격 컨텍스트 생성 후 이전 인게임 컨텍스트는 파기한다** — 파기 시점을 이렇게 정의해야 실패 화면·리플레이 동선에서 컨텍스트 수명이 모호해지지 않는다.

## 5. 씬별 상주 시스템

| 씬 | 주요 동작 시스템 |
|-----|------------------|
| 세이브 슬롯 선택 | 세이브 시스템 (슬롯 메타 표시, 생성/삭제) |
| 캠페인 맵 | 동적 캠페인 (노드/해금 표시), 난이도 (해금 상태), 상점/도감/도전과제 |
| 브리핑 | 미션 브리핑 (분기 반영 메시지, 힌트 표시 정책) |
| 로드아웃 | 로드아웃, 슬롯 시너지 (현재 빌드 시너지 표시), 장비 보유 검증 |
| 인게임 | 전투 관련 전 시스템 (전투처리흐름 문서 참고) |
| 클리어 평가 | 사전 처리된 평가·보상·해금·분기 결과의 **표시**, 알림 연출, 다음 행동 선택 (판정 시스템은 이 씬에 상주하지 않는다 — 6장 기준) |
| 실패 화면 | 표시 전용 (평가·보상 처리 없음) |

### 5.1 전역 상주 처리

씬과 무관하게 상시 동작하는 처리:

- 자동 저장 트리거: 미션 클리어 / 상점 거래 / 옵션 변경 / **출격 확정 시 현재 로드아웃 커밋** / **프리셋 생성·수정·덮어쓰기·삭제** / **시너지 발견 상태 갱신** — 현재 로드아웃은 "영속 상태"로 정의된 이상 커밋 즉시 저장되어야 한다 (출격 후 크래시로 세팅이 유실되지 않도록)
- 옵션 오버레이 접근
- 입력 장치 감지 (기반시스템_입력 문서 참고)

### 5.2 일시정지의 완전 정지 범위 (단일 기준)

인게임 일시정지 시 **게임플레이에 속한 모든 시간이 정지한다.** 본 절이 정지 대상의 단일 기준이며, 다른 문서는 본 절을 참조한다 (기반시스템_입력 문서의 일시정지 항목 등).

정지 대상: 스테이지 타임라인·스크롤 / 몬스터 AI·이동·발사 / 탄환·설치물·지속 효과의 틱 / 특수무장 쿨다운 / 슈퍼웨폰 게이지 자연 충전 / 무적·버프·디버프 지속 시간 / 보호막 재생 대기·누적 / 아이템 체류·소멸 시간 / 보스 페이즈 시간 트리거 / 램 재피격 타이머 / 플레이 기록 시간

정지하지 않는 것: 메뉴 UI 애니메이션·조작, 옵션 변경 적용

원칙: **게임플레이 시간 축에 속한 타이머는 예외 없이 전부 정지한다.** 새 시스템이 타이머를 추가할 때도 이 원칙을 따르며, 예외가 필요하면 본 문서에 명시적으로 등재해야 한다.

## 6. 미션 클리어 시 처리 순서와 씬의 관계

미션 클리어 시 데이터 처리(평가 집계 → 도전과제 → 분기 판정 → 보수 → 난이도 해금 → 자동 저장)는 **클리어 평가 씬 진입 전에 완료**된다. 평가 씬은 처리 결과를 표시만 한다. 상세 순서는 시스템_전투처리흐름 문서를 따른다.

**중복 실행 방지:** 동일한 클리어 결과에 대한 평가·보상·분기·도전과제·난이도 해금 처리는 **클리어 기록 식별자를 기준으로 단 한 번만 실행**한다. 평가 씬의 재진입이나 표시 연출 재생은 데이터 처리를 다시 실행하지 않는다 (씬 로드 재시도·중복 이벤트에 안전).

평가 씬에서 표시할 알림 종류 (표시 순서/방식은 UI 기획):
- 종합 평가 결과 (5개 항목 + 종합 랭크)
- 분기 미션 해금 알림
- 도전과제 달성/단계 클리어 + 보상 알림
- 난이도 해금 알림

## 7. 프로토타입 축소판

프로토타입 단계의 씬 구조는 다음으로 축소한다 (프로토타입 사양서와 정합).

```
디버그 시작 화면 (또는 즉시 시작)
  → 디버그 로드아웃 (기체 1종 고정, 무장/보호막 선택)
    → 스테이지 (1개)
      → 검증 리포트 (클리어 평가의 임시 대체)
        → 디버그 로드아웃으로 복귀 (즉시 리플레이)
```

- 타이틀/세이브/캠페인 맵/브리핑은 프로토타입 범위 외
- 검증 리포트 → 로드아웃 복귀 루프가 본편의 "리플레이" 흐름의 원형이 된다. 이 루프의 소요 시간(몇 초 만에 재출격 가능한가)을 프로토타입에서 측정해두면 본편 UI 설계의 기준이 된다

## 9. 확정 사항 요약

| 항목 | 결정 사항 |
|------|-----------|
| 씬 구성 | 타이틀 / 세이브 슬롯 / 캠페인 맵(허브) / 브리핑 / 로드아웃 / 인게임 / 클리어 평가 / 실패 화면 / 옵션(오버레이) |
