## 1. 개요

본 문서는 **스테이지 구조**의 세부 설계를 정의한다. 스테이지는 플레이어가 실제로 전투하는 단위이며, 자동 스크롤, 웨이브 구성, 적 등급, 스크롤 멈춤 구간 등의 규칙을 포함한다.

카메라 설정과 같은 기술적 구현 가이드는 본 문서의 범위 밖이며, 프로그래머 작업 영역에서 다룬다.

---

## 2. 스테이지 구성

### 2.1 스테이지 데이터

스테이지는 식별 정보, 배경 레이어(8장), 스크롤 속도 커브(3장), 웨이브 배열(4장), 이벤트 트리거 배열(5장), 최종 보스 참조, 종료 조건(9장)으로 구성된다.

(본 시스템의 데이터 항목 세부 정의는 별도의 데이터 테이블 문서에서 관리한다.)

## 3. 스크롤 시스템

### 3.1 자동 스크롤

스테이지는 **자동 스크롤**로 진행된다. 스크롤은 플레이어 이동과 완전히 독립적이며, 스크롤 속도는 스테이지 데이터에 의해서만 결정된다.

### 3.2 타임라인 기반 속도 제어

스크롤 속도는 **타임라인 기반 키프레임 방식**으로 제어한다. 스테이지의 시간축을 따라 스크롤 속도 키포인트를 배치하고, 키포인트 사이는 보간(선형 또는 커브)으로 자연스럽게 전환된다.

키프레임은 시간(스테이지 시작 후 경과), 목표 속도, 보간 방식(선형/커브/즉시)으로 구성된다.

**예시:**

| 시간 | 목표 속도 | 보간 | 설명 |
|------|-----------|------|------|
| 0초 | 1.0 | - | 기본 속도로 시작 |
| 25초 | 1.5 | 커브 | 서서히 가속, 고공 진입 연출 |
| 40초 | 1.5 | 선형 | 고속 유지 |
| 55초 | 1.0 | 커브 | 서서히 감속, 일반 구간 복귀 |

스크롤 멈춤 구간의 속도는 데이터에서 별도 키프레임으로 지정하지 않는다. 멈춤 트리거가 자동으로 속도를 0으로 강제한다 (5.4절 참고).

### 3.3 타임라인 방식을 채택한 이유

- **정밀 제어:** 스테이지 내 모든 시점의 스크롤 속도를 데이터로 정확하게 제어할 수 있다.
- **연출적 유리:** 보간을 통해 급격한 속도 변화 없이 자연스러운 전환이 가능하다. 즉시 전환도 지원하므로 필요 시 갑작스러운 변화도 가능.
- **에디터 친화:** 언리얼 커브 에셋으로 구현하면 시각적으로 속도 곡선을 편집할 수 있다.

### 3.4 스크롤 속도와 게임플레이

스크롤 속도는 단순한 연출이 아니라 게임플레이 변수이다.

- **고속 스크롤:** 지상 유닛이 화면에 머무는 시간이 짧아져 대지 무장의 DPS 중요도가 상승한다.
- **저속 스크롤:** 지상 유닛이 오래 머물러 범용 무장으로도 충분히 처리 가능하다.
- **멈춤 구간:** 스크롤이 멈추고 적을 처리하는 구간. 고정된 상태에서의 전투.

## 4. 웨이브 데이터

### 4.1 시간 기반 웨이브

적 등장은 **시간 기반**으로 관리한다. 스테이지 시작 후 경과 시간을 기준으로 웨이브가 트리거된다. 자동 스크롤이 시간에 따라 진행되므로, 시간 기반 웨이브와 스크롤 진행이 자연스럽게 동기화된다.

### 4.2 다중 동시 웨이브 지원

같은 시간에 **여러 웨이브가 동시에 트리거**될 수 있다. 연출적으로 동시 출현이 필요한 경우(예: 좌우 동시 진입, 다층 구성)를 위해 시스템적으로 지원한다.

### 4.3 웨이브 구성

웨이브는 트리거 시간(스테이지 시작 후 경과 시간)에 발생하며, 등장하는 몬스터의 배치 목록을 가진다.

### 4.4 몬스터 배치

배치 목록의 개별 항목은 등장 몬스터 참조, 등장 위치(화면 내 좌표), 등장 방향 또는 이동 경로, 등장 지연(웨이브 트리거 후 지연 시간)으로 구성된다. 등장 지연으로 동일 웨이브 내 순차 등장이 가능하다.

(본 시스템의 데이터 항목 세부 정의는 별도의 데이터 테이블 문서에서 관리한다.)

## 5. 이벤트 트리거 시스템

### 5.1 이벤트 트리거의 역할

이벤트 트리거는 스테이지 흐름을 제어하는 시점 단위의 사건이다. 스크롤 멈춤, 재개, 보스 진입 등의 처리를 시간축에 배치한다.

### 5.2 이벤트 트리거 구성

이벤트 트리거는 트리거 시간, 트리거 종류(멈춤/재개/보스 진입 등), 멈춤 트리거에 연결되는 재개 조건(적 전멸/특정 적 격파/시간 경과)으로 구성된다.

### 5.3 트리거 우선순위

웨이브 데이터와 이벤트 트리거가 같은 시간에 동시 발동하는 경우, **이벤트 트리거가 우선 처리**된다.

레벨 디자인 시 이러한 동시 발동을 의도적으로 만들지는 않으나, 발생 시 이벤트 트리거(특히 멈춤)가 먼저 적용되어 안정적인 스테이지 흐름을 유지한다.

### 5.4 멈춤 트리거의 자동 속도 제어

멈춤 트리거가 발동되면 **스크롤 속도가 자동으로 0으로 강제**된다. 디자이너가 스크롤 속도 커브에 별도로 0 키프레임을 추가할 필요가 없다. 멈춤 트리거 데이터만으로 멈춤 처리가 완결된다.

### 5.5 시간 일시정지 모델

멈춤 트리거 발동 시 **스테이지 시간 자체가 일시정지**된다. 단순히 스크롤만 멈추는 것이 아니라, 절대 시간축이 일시정지되어 후속 웨이브와 키프레임 트리거 시간이 모두 멈춤 동안 진행되지 않는다.

| 처리 항목 | 멈춤 중 동작 |
|-----------|--------------|
| 스크롤 속도 | 0 (자동 강제) |
| 후속 웨이브 트리거 시간 | 일시정지 (시간이 흐르지 않음) |
| 후속 키프레임 트리거 시간 | 일시정지 (시간이 흐르지 않음) |

이 모델을 채택한 이유는 디자이너가 "멈춤 구간은 별도로 정해진 웨이브만 처리"라는 단순한 모델로 레벨을 디자인할 수 있기 때문이다. 멈춤 중 후속 웨이브가 끼어드는 복잡한 상호작용이 발생하지 않으며, 멈춤 해제 후 데이터가 자연스럽게 이어진다.

### 5.6 멈춤-재개 흐름

1. 트리거 시간 도래 시 멈춤 트리거 발동
2. 스크롤 속도 자동으로 0
3. 스테이지 시간 일시정지
4. 멈춤 구간 전용 웨이브 또는 적 처리
5. 재개 조건 충족 (적 전멸, 특정 적 격파, 시간 경과)
6. 스테이지 시간 재개 (멈춤 진입 시점부터 그대로 이어감)
7. 스크롤 속도가 재개 시점의 키프레임 보간 값으로 복귀

### 5.7 재개 조건 종류

| 조건 | 설명 |
|------|------|
| 적 전멸 | 멈춤 구간에 등장한 모든 적 격파 |
| 특정 적 격파 | 지정된 적(엘리트, 중간보스 등) 격파 |
| 시간 경과 | 일정 시간 경과 후 자동 재개 |

### 5.8 보스 진입 처리

보스 진입 트리거가 발동되면 일련의 연출 시퀀스가 진행된다.

| 단계 | 처리 |
|------|------|
| 1 | 플레이어 조작 정지 |
| 2 | 플레이어 기체를 출격 시 초기 위치로 강제 이동 |
| 3 | WARNING 등 경고 메시지 출현 |
| 4 | 보스 등장 연출 |
| 5 | 보스 체력바 UI 출력 + 체력이 0에서 최대치까지 채워지는 애니메이션 |
| 6 | 플레이어 조작 재개 (보스전 진입) |

보스 진입 트리거는 일반적으로 멈춤 트리거와 함께 운영되며, 보스 페이즈 시스템과 연동되어 보스전이 시작된다.

## 6. 적 등급

### 6.1 4등급 구조

| 등급 | 역할 | 등장 방식 |
|------|------|-----------|
| 잡몹 | 웨이브 단위 기본 적 | 스크롤 중 지속 출현 |
| 엘리트 | 잡몹과 보스 사이의 중간 위협 | 스크롤 멈춤 구간 또는 스크롤 중 |
| 중간보스 | 스테이지 중반 강적 | 스크롤 멈춤 구간 |
| 보스 | 스테이지 최종 적 | 스크롤 멈춤 구간, 페이즈 시스템 적용 |

### 6.2 적 등급과 슈퍼웨폰 충전

적 등급에 따라 슈퍼웨폰 게이지 충전량이 차등 설정된다. 충전량은 몬스터 데이터 테이블에서 개별 관리한다.

## 7. 동적 캠페인 및 난이도에 의한 스테이지 변화

### 7.1 변화된 스테이지는 별도 스테이지로 취급

다음 두 경우 모두 **변화된 스테이지를 별도의 스테이지 데이터로 관리**한다.

| 변화 요인 | 처리 |
|-----------|------|
| 동적 캠페인 분기 | 분기 충족된 스테이지를 별도 데이터로 (예: "2-1스테이지") |
| 난이도 차등 | 난이도별 별도 스테이지 데이터 (Normal / Hard / 3단계) |

### 7.2 별도 스테이지 취급을 채택한 이유

- **데이터 독립성:** 변화된 웨이브 구성, 적 배치, 스크롤 속도, 패턴 등을 독립적으로 관리할 수 있다.
- **기존 시스템 유지:** 스테이지 시스템의 구조를 변경하지 않고 변화 요인을 구현할 수 있다.
- **클리어 평가 분리:** 원본 스테이지와 변화 스테이지의 클리어 평가를 독립적으로 관리할 수 있다.
- **단일 메커니즘:** 동적 캠페인과 난이도 차등 모두 동일한 "스테이지 치환" 메커니즘으로 처리되어 일관성이 유지된다.

### 7.3 캠페인 흐름에서의 처리

게임이 미션을 로드할 때 다음 순서로 스테이지 ID를 결정한다.

1. 미션 ID 확인
2. 현재 난이도 확인
3. 동적 캠페인 분기 조건 충족 여부 확인
4. 위 조건 조합에 대응하는 스테이지 ID로 로드

플레이어에게는 동일한 미션으로 보이지만 내부적으로는 조건에 따라 다른 스테이지 데이터가 사용된다.

### 7.4 스테이지 수 예상

미션 수 × 난이도 3단계 × 동적 캠페인 분기 조합으로 스테이지 데이터 수가 늘어난다. 모든 조합이 반드시 차등 제작될 필요는 없으며, 변화가 필요한 조합만 별도 데이터로 제작한다.

## 8. 배경 시스템

### 8.1 다중 레이어 구조

스테이지 배경은 **다중 레이어**로 구성된다. 각 레이어는 독립적인 스크롤 속도 비율을 가질 수 있다.

| 레이어 예시 | 스크롤 속도 비율 (예시) |
|-------------|--------------------------|
| 메인 배경 (지면) | 100% (스크롤 속도와 동일) |
| 중간 레이어 (구름 등) | 60~80% |
| 원경 레이어 (별, 먼 산 등) | 20~40% |

이는 패럴랙스 스크롤 기법으로 깊이감을 표현한다.

### 8.2 배경 데이터

배경 레이어별로 다음 항목을 데이터로 관리한다.

| 항목 | 설명 |
|------|------|
| 레이어 ID | 레이어 식별자 |
| 아트 에셋 | 배경 이미지/3D 모델 참조 |
| 스크롤 속도 비율 | 메인 스크롤 속도 대비 비율 (0.0 ~ 1.0) |
| 깊이 | 카메라로부터의 깊이 (렌더링 순서) |

## 9. 스테이지 종료 조건

### 9.1 기본 모드: 보스 격파

기본 게임 모드에서 스테이지 종료 조건은 **보스 본체 격파**이다. 보스가 격파되면 스테이지가 종료되고 클리어 평가 화면으로 진입한다.

### 9.2 미래 확장: 다른 종료 조건

이벤트 미션이나 챌린지 모드 같은 특수 모드에서는 다른 종료 조건이 사용될 수 있다.

| 종료 조건 | 활용 예시 |
|-----------|-----------|
| 시간 경과 | 일정 시간 생존 미션 |
| 무한 웨이브 | 챌린지 모드의 점수 경쟁 |
| 특정 목표 달성 | 이벤트 미션의 특수 목표 |

이러한 모드는 본 시스템의 시스템 구조를 그대로 활용하되 종료 조건만 다르게 설정하는 방식으로 확장 가능하다.

## 10. 미션과 스테이지의 관계

### 10.1 구조

- **기본:** 1미션 = 1스테이지
- **확장:** 1미션 = N스테이지 (시스템적 허용)

미션은 캠페인 흐름상의 단위, 스테이지는 실제 플레이 단위로 구분된다. 다중 스테이지 미션에서는 스테이지 간 로드아웃 재세팅이 가능하다.

---

## 11. 클리어 평가와의 연동

### 11.1 평가 데이터 집계

스테이지 진행 중 발생하는 격파, 피탄, 사망 등의 데이터는 클리어 평가 시스템의 평가 항목으로 집계된다.

| 평가 항목 | 집계 방식 |
|-----------|-----------|
| 공중/지상 격파율 | 스테이지 내 등장 적 수 vs 격파 수 비율 |
| 피탄 횟수 | 스테이지 내 모든 피격 누적 (보호막 흡수 포함) |
| 스코어 | 스테이지 내 모든 스코어 가산 |
| 사망 횟수 | 스테이지 내 사망 횟수 |

### 11.2 변화 스테이지의 평가 처리

동적 캠페인 또는 난이도 차등으로 별도 스테이지 데이터가 사용되는 경우, 평가 데이터는 **해당 스테이지 ID 기준으로 독립 집계**된다.

| 케이스 | 평가 처리 |
|--------|-----------|
| 같은 미션 ID, 다른 스테이지 데이터 | 스테이지 ID별로 독립적인 평가 기록 |
| 같은 스테이지 ID, 다른 난이도 | 스테이지 ID + 난이도 조합별로 독립 기록 |

이로 인해 같은 미션이라도 어떤 조건(분기, 난이도)에서 클리어했는지에 따라 평가 데이터가 분리되며, 도전과제 추적도 정확하게 이루어진다.

## 12. 세부 수치 결정 시점

다음 항목들은 프로토타입 단계에서 실제 플레이를 통해 결정한다.

- 스테이지 길이 (분)
- 웨이브 밀도 (단위 시간당 적 수)
- 스크롤 기본 속도 및 고속/저속 속도 범위
- 멈춤 구간 빈도 및 길이
- 배경 레이어 스크롤 비율의 정확한 값

|-------------|-----------|

| 동적 캠페인 시스템 | 이전 미션 결과에 따른 스테이지 분기 (별도 스테이지 데이터) |

| 클리어 평가 시스템 | 스테이지 내 평가 데이터 집계 |
| 슈퍼웨폰 시스템 | 적 격파 시 게이지 충전 |

## 15. 확정 사항 요약

| 항목 | 결정 사항 |
|------|-----------|
| 스크롤 방식 | 자동 스크롤, 플레이어와 완전 독립 |
| 스크롤 속도 제어 | 타임라인 기반 키프레임 + 보간 (선형/커브/즉시) |
| 멈춤 구간 속도 처리 | 멈춤 트리거가 자동으로 속도 0 강제 (별도 키프레임 불필요) |
| 웨이브 기반 | 시간 기반 (스테이지 시작 후 경과 시간) |
| 다중 동시 웨이브 | 지원 |
| 트리거 우선순위 | 동시 발동 시 이벤트 트리거 우선 |
| 시간 모델 | 멈춤 시 스테이지 시간 일시정지 (후속 웨이브/키프레임도 정지) |
| 멈춤 재개 | 멈춤 진입 시점부터 시간 그대로 이어감 |
| 재개 조건 | 적 전멸, 특정 적 격파, 시간 경과 |
| 보스 진입 처리 | 조작 정지 → 위치 초기화 → WARNING → 보스 등장 → 체력바 채움 → 조작 재개 |
| 적 등급 | 잡몹 / 엘리트 / 중간보스 / 보스 (4등급) |
| 변화 요인 | 동적 캠페인 / 난이도 차등 (둘 다 별도 스테이지 데이터로 처리) |
| 미션-스테이지 관계 | 1:1 기본, 1:N 허용 |
| 배경 시스템 | 다중 레이어 + 패럴랙스 스크롤 |
| 종료 조건 (기본) | 보스 본체 격파 |
| 종료 조건 (확장) | 시간 경과, 무한 웨이브, 특수 목표 (이벤트/챌린지 모드) |
| 평가 데이터 집계 | 스테이지 ID + 난이도 조합별 독립 기록 |
| 카메라 설정 | 본 문서 범위 밖 (프로그래머 영역) |
| 세부 수치 | 프로토타입에서 결정 |
