## 1. 개요

본 문서는 전투 중 발생하는 주요 이벤트의 **시스템 간 처리 흐름과 호출 순서**를 정의한다. 데이터 흐름 추적을 통해 발견된 시스템 간 정합성을 통합 관리하며, 처리 순서가 게임 결과에 영향을 주는 케이스를 명확히 한다.

본 문서는 시스템 명세 차원의 처리 흐름을 다루며, 구체적인 구현 방식(매 프레임 처리, 이벤트 큐 등)은 프로그래머 영역에서 결정한다.

## 2. 일반 적 격파 이벤트

### 2.1 트리거 조건

플레이어 무장의 데미지가 적에게 적용되어 적 체력이 0 이하가 된 시점.

### 2.2 처리 순서

적 격파 시점에 다음 순서로 처리된다.

```
[1] 격파 점수 계산 (스코어링)
   - 격파 시점의 격파 속도 배율 계산
   - 격파 시점의 현재 체인 배율 적용
   - 최종 점수 = 기본 점수 × 격파 속도 배율 × 체인 배율
   - 누적 스코어에 가산

[2] 체인 카운트 갱신 (스코어링)
   - 체인 카운트 +1
   - 새 체인 배율 갱신 (다음 격파부터 적용)
   - 체인 유지 타이머 리셋

[3] 격파율 카운트 (클리어 평가)
   - 적의 속성에 따라 공중/지상 격파율 누적
   - 양면 속성이면 양쪽 다 카운트

[4] 슈퍼웨폰 게이지 충전 (슈퍼웨폰)
   - 적 데이터의 게이지 충전량 적용
   - 게이지 100% 도달 시 1스톡 생성

[5] 아이템 드롭 (아이템 드롭)
   - 적 데이터의 드롭 아이템 배열에 따라 아이템 생성
   - 격파 위치에서 랜덤 방향 튕김

[6] 적 객체 제거
```

### 2.3 처리 순서의 게임 결과 영향

처리 순서가 결과에 영향을 주는 케이스를 명확히 정의한다.

#### 2.3.1 점수 계산 → 체인 카운트 갱신 (순서 중요)

점수 계산은 **격파 시점의 현재 체인 배율**로 수행되어야 한다. 체인 카운트가 먼저 갱신되면 새 배율이 적용되어 의도와 다른 결과가 나온다.

올바른 순서:
- 1번째 적 격파: 배율 1.0 적용 → 격파 후 1.01로 갱신
- 2번째 적 격파: 배율 1.01 적용 → 격파 후 1.02로 갱신

#### 2.3.2 격파율 카운트 → 슈퍼웨폰 충전 (순서 무관)

이 둘은 서로 영향을 주지 않으므로 순서가 결과에 영향을 미치지 않는다. 하지만 일관성을 위해 명시된 순서를 따른다.

#### 2.3.3 슈퍼웨폰 충전 → 아이템 드롭 (순서 무관)

마찬가지로 순서 무관. 명시된 순서를 따른다.

### 2.4 동시 격파 처리

같은 프레임 내에 여러 적이 동시에 격파되는 경우(광역 무기, 슈퍼웨폰 등):

```
동시 격파의 정의: 같은 프레임 내에서 격파된 모든 적

처리 흐름:
[1] 동시 격파된 모든 적에 대해 점수 계산
   - 모든 적에게 격파 시점의 동일한 체인 배율 적용
   - 각 적의 격파 점수 합산하여 누적 스코어에 가산

[2] 체인 카운트 일괄 갱신
   - 격파된 적의 수만큼 체인 카운트 한꺼번에 증가
   - 새 체인 배율로 갱신 (다음 격파부터 적용)

[3] 모든 격파된 적에 대해 격파율 카운트, 슈퍼웨폰 충전, 아이템 드롭 처리

[4] 적 객체 제거
```

이 방식의 의도:
- 동시 격파된 모든 적이 같은 가치(같은 배율)를 가져 처리 순서에 따른 결과 차이 없음
- 단순하고 직관적
- 다중 격파의 보너스는 체인 카운트가 한꺼번에 증가하는 형태로 자연스럽게 반영

## 3. 플레이어 피격 이벤트

### 3.1 트리거 조건

적의 공격(탄환, 근접 공격 등)이 플레이어 히트박스와 충돌한 시점.

### 3.2 처리 순서

```
[1] 무적 시간 확인 (생존)
   - 피격 후 무적 시간 또는 리스폰 무적 시간 상태이면 데미지 무시 (이벤트 종료)

[2] 보호막 잔량 확인 (생존)
   - 보호막 ≥ 1: [3]으로 진행
   - 보호막 = 0: [4]로 진행

[3] 보호막 데미지 처리 (생존)
   - 보호막이 데미지 흡수 (잔량보다 큰 데미지도 1회 완전 흡수)
   - 보호막 잔량 = max(0, 잔량 - 데미지)
   - 보호막이 0이 되는 경우: 보호막 파괴 시 특수 효과 발동 (보호막 장비 데이터에 따라)
   - 피탄 횟수 +1 (클리어 평가)
   - 무적 시간 발동 안 함
   - 이벤트 종료

[4] 체력 데미지 처리 (생존)
   - 체력 = max(0, 체력 - 데미지)
   - 피탄 횟수 +1 (클리어 평가)
   - 체력 > 0: [5]로 진행
   - 체력 = 0: [6]으로 진행

[5] 피격 후 무적 시간 발동 (생존)
   - 무적 타이머 시작
   - 이벤트 종료

[6] 사망 처리 (생존)
   - 사망 횟수 +1 (클리어 평가)
   - 잔기 확인:
     - 잔기 ≥ 1: 잔기 1 차감 → 리스폰 처리 ([7])
     - 잔기 = 0: 미션 실패 ([8])

[7] 리스폰 처리 (생존)
   - 플레이어 위치 초기 위치로 이동
   - 체력/보호막 풀 상태로 복구
   - 리스폰 무적 시간 발동
   - 이벤트 종료

[8] 미션 실패
   - 미션 종료, 미션 선택 화면으로 복귀
   - 미션 클리어 평가는 산출되지 않음
```

### 3.3 처리 순서의 게임 결과 영향

#### 3.3.1 무적 확인 → 보호막 확인 (순서 중요)

무적 시간 중에는 보호막도 데미지를 받지 않아야 하므로, 무적 확인이 먼저 이루어져야 한다.

#### 3.3.2 보호막 데미지 → 피탄 카운트 (순서 무관)

피탄 카운트는 보호막 흡수 여부와 무관하게 모든 피격에 1회 가산되므로 순서 무관.

## 4. 보스 파츠 공격 이벤트

### 4.1 트리거 조건

플레이어 무장의 데미지가 보스 파츠에 적용된 시점.

### 4.2 처리 순서

```
[1] 속성 일치 확인 (지상/공중 판정 분리)
   - 무장 속성 vs 파츠 속성 비교
   - 속성 불일치: 데미지 무시, 탄환 관통 (이벤트 종료)
   - 속성 일치: [2]로 진행

[2] 데미지 적용 (보스 페이즈)
   - 파츠 체력 = max(0, 파츠 체력 - 데미지)
   - 본체 체력 = max(0, 본체 체력 - 데미지)  # 동일 데미지가 본체에도 적용

[3] 파츠 파괴 확인 (보스 페이즈)
   - 파츠 체력 = 0: 파츠 파괴 처리 ([4])
   - 파츠 체력 > 0: [6]으로 진행

[4] 파츠 파괴 처리 (보스 페이즈)
   - 파츠 콜리전 비활성화
   - 파츠 공격 패턴 중단
   - 파츠 파괴 점수 가산 (스코어링)
   - 파츠 파괴 시 아이템 드롭 (아이템 드롭, 데이터에 따라)
   - 체인 카운트 +1 (스코어링) — 파츠 파괴를 격파의 일종으로 처리
   - 파츠 재생 가능한 경우: 재생 타이머 시작
   - 파츠 파괴가 페이즈 전환 트리거인 경우: 페이즈 전환 처리

[5] 본체 체력 0 확인 (보스 페이즈)
   - 본체 체력 = 0: 보스 격파 → 미션 클리어 흐름으로 진입

[6] 이벤트 종료
```

### 4.3 보스 본체 직접 공격

보스 본체에 직접 데미지를 주는 경우는 [2]의 본체 체력 감소만 발생하고, 파츠 체력은 영향받지 않는다.

## 5. 아이템 획득 이벤트

### 5.1 트리거 조건

플레이어 기체가 드롭된 아이템에 접촉한 시점.

### 5.2 처리 순서 (아이템 종류별)

#### 5.2.1 회복 아이템

```
[1] 체력 잔량 확인 (생존)
   - 체력 < 최대 체력: [2]로 진행
   - 체력 = 최대 체력: [3]으로 진행

[2] 체력 회복 (생존)
   - 체력 = min(최대 체력, 체력 + 회복량)
   - 이벤트 종료

[3] 보호막 회복 (생존)
   - 보호막 = min(최대 보호막, 보호막 + 회복량)
   - 이벤트 종료
```

#### 5.2.2 점수 아이템

```
[1] 고정 점수 가산 (스코어링)
   - 누적 스코어에 아이템의 고정 점수 가산
   - 격파 속도 배율, 체인 배율 미적용
```

#### 5.2.3 슈퍼웨폰 충전 아이템

```
[1] 게이지 충전 (슈퍼웨폰)
   - 아이템의 충전량만큼 게이지 증가
   - 게이지 100% 도달 시 1스톡 생성
```

### 5.3 다중 동시 획득

같은 프레임 내에 여러 아이템에 동시 접촉한 경우:
- 모든 아이템 획득
- 각 아이템 종류별 처리를 모두 수행
- 회복 아이템이 여러 개면 누적 회복

### 5.4 무적 시간과 무관

플레이어가 무적 시간 상태에서도 아이템 획득은 정상적으로 처리된다. 무적 시간은 적 공격에 대한 처리이며, 아이템 획득은 무적 상태와 독립적으로 동작한다.

## 6. 미션 클리어 이벤트

### 6.1 트리거 조건

보스 본체 체력이 0이 되어 보스가 격파된 시점 (기본 모드 기준).

### 6.2 처리 순서

```
[1] 미션 클리어 판정
   - 스테이지 종료
   - 게임 진행 정지

[2] 종합 평가 데이터 집계 (클리어 평가)
   - 공중 격파율, 지상 격파율 계산
   - 피탄 횟수 합계
   - 누적 스코어 확정
   - 사망 횟수 합계
   - 클리어 시간 기록

[3] 종합 랭크 산출 (클리어 평가)
   - 5개 평가 항목의 개별 랭크 산출
   - 가중치 적용하여 종합 랭크 산출
   - 적용 불가 항목은 산출에서 제외

[4] 평가 데이터 보존 (클리어 평가)
   - 스테이지 ID + 난이도 조합별로 평가 결과 저장
   - 모든 플레이 기록 누적 보존

[5] 도전과제 진행도 갱신 (장비 해금)
   - 평가 데이터를 도전과제 조건에 대조
   - 누적 추적형: 진행도 카운트 증가
   - 달성 판별형: 조건 충족 여부 판정

[6] 도전과제 단계 클리어 처리 (장비 해금)
   - 단계 클리어 조건 도달 시:
     - 보상 지급 (장비 / 기체 / 재화)
     - 게임 전체 공유 데이터 갱신
     - 다음 단계 활성화

[7] 분기 미션 해금 검사 (동적 캠페인)
   - 미션의 분기 조건 충족 여부 확인 (AND 다중 조건)
   - 모든 조건 충족 시: 분기 미션 해금
   - 캠페인 진행 데이터 갱신

[8] 미션 클리어 보수 지급 (장비 해금)
   - 종합 랭크에 따라 재화 지급
   - 세이브 단위 재화 잔액에 추가

[9] 난이도 해금 처리 (난이도)
   - 클리어한 난이도가 Normal: Hard 해금
   - 클리어한 난이도가 Hard: Nightmare 해금
   - 게임 전체 공유 데이터 갱신

[10] 자동 저장 (세이브)
   - 세이브 슬롯 데이터 저장
   - 게임 전체 공유 데이터 저장

[11] 클리어 평가 화면 진입 (클리어 평가)
   - 평가 결과 표시
   - 알림 표시 (분기 해금, 도전과제 달성, 시너지 발견 등)
   - 액션 선택 대기 (미션 선택으로 / 리플레이)
```

### 6.3 미션 실패 시 처리

플레이어 사망으로 잔기가 0이 된 경우:

```
[1] 미션 실패 판정 (생존)

[2] 평가 데이터 미산출
   - 미션 실패 시 클리어 평가는 산출되지 않음
   - 평가 기록 보존 안 됨

[3] 도전과제 진행도 미갱신
   - 미션 실패는 도전과제 조건 충족으로 처리되지 않음
   - 단, "도전 시도 횟수" 같은 별도 추적이 있다면 그건 별개로 처리

[4] 미션 선택 화면으로 복귀 (동적 캠페인)
```

## 7. 처리 흐름의 시스템 간 일관성

### 7.1 호출 관계 요약

각 이벤트에서 호출되는 시스템들의 우선순위.

| 이벤트 | 1순위 | 2순위 | 3순위 | 4순위 |
|--------|-------|-------|-------|-------|
| 적 격파 | 스코어링 (점수) | 스코어링 (체인) | 클리어 평가, 슈퍼웨폰, 아이템 드롭 | 적 객체 제거 |
| 플레이어 피격 | 생존 (무적 확인) | 생존 (보호막/체력) | 클리어 평가 (피탄/사망) | 생존 (리스폰/실패) |
| 보스 파츠 공격 | 판정 분리 | 보스 페이즈 (데미지) | 보스 페이즈 (파괴 판정) | 스코어링/아이템 드롭/페이즈 전환 |
| 아이템 획득 | 종류 판별 | 해당 시스템 (생존/스코어링/슈퍼웨폰) | - | - |
| 미션 클리어 | 클리어 평가 (집계) | 장비 해금 (도전과제) | 동적 캠페인/난이도 | 세이브 |

### 7.2 데이터 단방향 흐름

전투 처리 흐름은 기본적으로 **데이터의 단방향 흐름**을 따른다. 이벤트 발생 시스템 → 처리 시스템들로 데이터가 전달되며, 역방향 호출은 발생하지 않는다.

예외: 미션 클리어 이벤트의 처리 중 시스템 간 호출이 일부 양방향으로 발생할 수 있으나, 호출 순서가 명확히 정의되어 순환 참조가 발생하지 않는다.

## 10. 확정 사항 요약

| 항목 | 결정 사항 |
|------|-----------|
| 적 격파 처리 순서 | 점수 → 체인 갱신 → 격파율/슈퍼웨폰/아이템드롭 → 객체 제거 |
| 동시 격파 정의 | 같은 프레임 내 격파된 모든 적 |
| 동시 격파 처리 | 모든 적에게 동일 배율 적용, 체인 카운트 한꺼번에 증가 |
| 플레이어 피격 처리 순서 | 무적 확인 → 보호막 확인 → 데미지 적용 → 무적 발동/사망 처리 |
| 보스 파츠 공격 처리 | 속성 확인 → 파츠+본체 데미지 → 파괴 판정 → 파괴 처리 → 본체 체력 확인 |
| 미션 클리어 처리 순서 | 평가 집계 → 도전과제 갱신 → 분기 검사 → 보수 → 난이도 해금 → 자동 저장 → 평가 화면 |
| 데이터 흐름 | 단방향 (이벤트 → 처리 시스템) |
