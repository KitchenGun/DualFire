## 1. 개요

본 문서는 **장비 해금 시스템**의 세부 설계를 정의한다. 장비와 기체의 획득은 상점 구매와 도전과제 해금의 이중 구조로 운영되며, 도전과제 시스템과 통합하여 관리한다.

---

## 2. 재화 시스템

### 2.1 단일 통화

게임 내 재화는 **단일 통화 1종**만 사용한다. 복수 재화는 도입하지 않는다.

### 2.2 단일 통화를 채택한 이유

- **직관성:** 플레이어가 재화 관리에 인지 부담을 느끼지 않는다.
- **가치 판단 용이:** 모든 장비의 가격을 하나의 축으로 비교할 수 있다.
- **시스템 단순화:** 재화 간 교환 비율, 재화별 획득처 같은 복잡한 구조가 불필요하다.

### 2.3 재화 획득 경로

재화 획득 경로는 다음 두 가지로 한정한다.

| 획득 경로 | 보존 단위 | 설명 |
|-----------|-----------|------|
| 미션 클리어 보수 | 세이브 단위 | 종합 랭크에 따라 차등 지급 |
| 도전과제 보상 | 게임 전체 공유 | 도전과제 달성 시 보상으로 재화 가능 |

미션 클리어 보수 외의 다른 정기적 획득 경로(점수 아이템, 시간 보너스 등)는 두지 않는다. 점수 아이템은 스코어링에만 반영되며 재화로 전환되지 않는다.

### 2.4 재화 등급 차등

미션 클리어 보수는 클리어 평가의 **종합 랭크**에 따라 차등 지급된다.

| 종합 랭크 | 보수 |
|----------|------|
| S | 최대 |
| A | 높음 |
| B | 보통 |
| C | 낮음 |
| D | 최소 |

구체적인 보수 수치는 밸런싱 단계에서 결정한다.

### 2.5 재화 사용 제약

| 항목 | 처리 |
|------|------|
| 장비/기체 판매 | 없음 (한 번 산 장비는 환불 불가) |
| 환불 | 없음 |
| 동적 가격 | 없음 (할인 이벤트 등 미적용) |

플레이어가 신중하게 구매하도록 환불을 두지 않으며, 가격은 항상 데이터에 정의된 고정값.

## 3. 상점 시스템

### 3.1 상점의 역할

상점은 **캠페인 진행에 따른 자연스러운 장비 확보** 수단이다. 캠페인을 진행하면서 보수를 모아 장비를 구매하여 옵션을 넓히는 구조.

### 3.2 상점 접근

상점은 **미션 선택 화면에서 UI를 통해 접근**한다. 별도의 상점 화면이 아닌, 캠페인 흐름 속에서 자연스럽게 접근 가능한 구조.

### 3.3 상점 취급 장비

상점에서는 **기본~중급 장비**를 취급한다. 모든 미션을 클리어할 수 있는 충분한 성능의 장비군이 상점에 포함되며, 상점 장비만으로 게임 클리어가 가능하다.

### 3.4 가격 구조

- 단일 통화로 구매
- 장비별 가격 차등 설정
- 고급 장비일수록 가격이 높아지며, 최종 단계 장비는 매우 높은 가격이 될 수 있다
- 구체적 가격 수치는 밸런싱 단계에서 결정

### 3.5 기체 구매

기체도 상점에서 구매 가능하다. 기본~중급 기체가 상점에서 취급되며, 동일한 단일 통화로 구매한다.

## 4. 도전과제 해금

### 4.1 도전과제 해금의 역할

도전과제 해금은 **플레이 숙련의 보상**이다. 도전적인 조건을 달성하면 특수한 장비, 기체, 재화가 해금된다.

### 4.2 해금 대상

도전과제 해금 대상은 다음 항목들이다.

| 보상 종류 | 대상 |
|-----------|------|
| 장비 | 극단적 특성을 가진 사이드그레이드 장비 |
| 기체 | 고급~특수 기체 |
| 재화 | 일정량의 게임 내 재화 |

이들은 상점 장비의 단순 상위호환이 아니라, 리스크-보상형의 독특한 성격을 가진다.

### 4.3 조건 유형

| 조건 유형 | 예시 |
|-----------|------|
| 특정 미션 특정 랭크 클리어 | "미션 5를 종합 S랭크로 클리어" |
| 엔딩 도달 | "Normal 난이도 엔딩 도달" |
| 난이도별 엔딩 | "Hard 난이도 엔딩 도달" |
| 특수 클리어 조건 | "슈퍼웨폰 미사용으로 보스 격파" |
| 평가 항목 누적 달성 | "공중 격파율 S랭크 3회 달성" |
| 미션 한정 누적 | "1-1 미션의 공중 격파율 S랭크 3회" |

조건 데이터는 미션 ID, 평가 항목, 등급, 횟수 등의 다축 파라미터로 유연하게 표현 가능하도록 설계한다.

### 4.4 미채용 조건 유형

| 미채용 조건 | 사유 |
|-------------|------|
| 누적 플레이 횟수 | 무작정 반복시키는 구조. 플레이어 숙련과 무관. |
| 특정 빌드 강제 | 빌드 자유도 철학에 위배. 플레이 스타일을 "살짝 조정"하는 수준까지만 허용. |

## 5. 보존 단위 차별화

### 5.1 차별화 정책

장비, 기체, 재화의 보존 단위는 획득 경로에 따라 차별화된다.

| 자원 | 획득 경로 | 보존 단위 |
|------|-----------|-----------|
| 장비 | 상점 구매 | 세이브 단위 |
| 장비 | 도전과제 해금 | **게임 전체 공유** |
| 기체 | 상점 구매 | 세이브 단위 |
| 기체 | 도전과제 해금 | **게임 전체 공유** |
| 재화 | 미션 클리어 보수 | 세이브 단위 |
| 재화 | 도전과제 보상 | **게임 전체 공유 (누적 기록) + 새 세이브 시작 시 일시 지급** |

### 5.1.1 도전과제 재화 보상 동작 상세

도전과제로 받은 재화는 다음과 같이 처리된다:

- **달성 즉시:** 현재 세이브의 재화 잔액에 가산 + 게임 전체 공유 누적 기록에 추가
- **새 세이브 시작 시:** 그동안 도전과제로 받은 누적 재화 합계가 새 세이브의 초기 재화 잔액으로 일시 지급
- **이후 사용/소비:** 해당 세이브 슬롯 내에서 일반 재화처럼 사용 (소비되어도 다른 세이브에는 영향 없음)

이 정책의 의도는 새 세이브에서도 도전과제로 얻은 재화를 초기 자원으로 활용하여, 다양한 빌드와 도전을 더 빠르게 시도할 수 있도록 하기 위함이다. 장비/기체는 영구 공유, 재화는 누적 기록 기반의 세이브 단위 일시 지급이라는 차별화된 정책으로 운영된다.

### 5.2 차별화를 채택한 이유

- **2회차 동기 강화:** 새 세이브를 시작해도 도전과제로 얻은 보상은 그대로 유지되어, 초반부터 더 다양한 빌드 탐색 가능
- **숙련 보상 영속화:** 도전과제는 플레이어의 숙련 결과이므로 영구히 보장
- **다회차 의미 유지:** 즉시 리플레이 방식으로 다회차의 의미가 약한 본 게임에서, 새 세이브의 차별화 요소를 도전과제 영속 보상으로 부여

## 6. 장비 등급

### 6.1 내부 등급 구조

장비는 내부적으로 등급이 구분되어 있으나, **플레이어에게 등급 라벨을 직접 노출하지 않는다.**

| 내부 등급 | 획득 방법 | 포지셔닝 |
|-----------|-----------|----------|
| B | 상점 구매 | 기본 성능. 캠페인 초반 사용. |
| A | 상점 구매 | 정석 장비. 모든 미션 클리어 가능한 충분한 성능. |
| S | 도전과제 해금 | 사이드그레이드. 극단적 특성의 리스크-보상형. |

### 6.2 등급 비노출 사유

- 플레이어가 "S급이니까 무조건 좋겠지"라는 선입견 없이, 직접 써보면서 장비의 특성을 파악하게 한다.
- 상점 장비와 해금 장비의 차이를 라벨이 아닌 체감으로 느끼게 하여, 장비 탐색의 재미를 유지한다.

### 6.3 S급 밸런스 원칙

S급 장비는 A랭크의 상위호환이 되어서는 안 된다. 극단적 특성을 가진 사이드그레이드로 설계하며, 장점과 단점이 공존해야 한다.

**예시 방향성:**
- S급 대공 무장: DPS 매우 높지만 사거리 극단적으로 짧음
- S급 보호막: 내구도 높지만 피격 시 이동속도 감소
- S급 슈퍼웨폰: 효과 강력하지만 소비 스톡 2

이를 통해 A랭크 정석 장비가 쓸모없어지는 것을 방지하고, S급 장비는 "쓸까 말까" 고민 자체가 재미가 되는 포지션을 유지한다.

## 7. 도전과제 시스템

### 7.1 통합 관리

장비/기체/재화 해금 조건과 순수 트로피형 도전과제를 **하나의 도전과제 테이블**로 통합 관리한다.

### 7.2 도전과제 구성

도전과제는 식별 정보(이름, 설명)와 단계 배열로 구성된다. 각 단계는 달성 조건(조건 유형 + 구체 파라미터), 게임 내 보상(장비/기체/재화, 선택적), 트로피 보상(선택적), 진행도 추적 방식(누적 추적/달성 판별)을 가진다.

게임 내 보상과 트로피 보상은 **양립 가능**하다. 한 단계에서 게임 내 보상과 트로피를 모두 줄 수 있다.

(본 시스템의 데이터 항목 세부 정의는 별도의 데이터 테이블 문서에서 관리한다.)

### 7.3 단계적 도전과제

하나의 도전과제는 **여러 단계**를 가질 수 있다. 1단계 클리어 → 2단계 활성화 → ... 의 순서로 진행된다.

**예시:** "공중 격파율 S랭크 누적"
- 1단계: 3회 달성 → 게임 내 보상 1
- 2단계: 5회 달성 → 게임 내 보상 2
- 3단계: 10회 달성 → 게임 내 보상 3 + 트로피

각 단계별로 조건과 보상이 독립적으로 설정 가능하다. 단일 도전과제 ID로 단계 진행을 관리하며, 별도 도전과제로 분리하지 않아 도감 UI에서도 통합되어 표시된다.

### 7.4 진행도 추적 방식

도전과제 단계의 진행도 추적은 2가지 방식을 지원한다.

| 방식 | 동작 | 적용 예시 |
|------|------|-----------|
| 누적 추적 | 플레이어가 수행한 데이터를 누적하여 목표치 도달 여부 확인 | "공중 격파율 S랭크 3회 달성" (현재 2/3) |
| 달성 판별 (True/False) | 특정 조건의 충족 여부만 확인 | "Normal 엔딩 도달" (달성/미달성) |

### 7.5 진행도 표시

도전과제 진행도는 **플레이어에게 표시**한다.

- 누적 추적: 현재 달성 상태(예: 2/3)를 보여줌
- 달성 판별: 달성/미달성 상태를 보여줌

진행도가 목표치에 도달하면 단계 클리어 처리되며, 다음 단계가 자동 활성화된다. 누적 추적이 목표를 초과하는 경우는 발생하지 않는다 (3/3에서 클리어, 다음 단계가 새로 활성).

## 8. 도전과제 데이터 보존

### 8.1 보존 단위

도전과제 시스템은 두 가지 보존 단위의 데이터를 함께 관리한다.

| 데이터 | 보존 단위 | 설명 |
|--------|-----------|------|
| 도전과제 정의 | 게임 정적 데이터 | 시스템이 가진 도전과제 목록 (조건, 보상 등). 변하지 않음. |
| 진행도 (현재 카운트) | 세이브 단위 | 평가 데이터 기반 누적 카운트. 세이브마다 새로 시작. |
| 달성 기록 | 게임 전체 공유 | 한 번이라도 달성한 도전과제 단계 기록. 영구 보존. |

### 8.2 진행도 추적 단위

누적 도전과제의 진행도는 **세이브 단위로 추적**된다. 한 세이브 안에서 누적이 시작되어 한 세이브 안에서 달성되어야 한다. 세이브 간에 누적이 합산되지 않는다.

이 정책의 의도:
- 다회차 의미 유지: 세이브를 여러 개 만들어 진행도를 분산시켜 빠르게 달성하는 우회 플레이 방지
- 도전감 유지: 한 세이브 내 달성이라는 명확한 목표 제공
- 보상의 영속성: 달성한 보상은 게임 전체 공유로 모든 세이브에서 사용 가능

### 8.3 새 세이브에서의 처리

새 세이브를 시작했을 때, 이전 세이브에서 달성한 도전과제는 다음과 같이 처리된다.

| 항목 | 처리 |
|------|------|
| 도전과제 진행도 | 새 세이브에서 0부터 시작 (평가 데이터가 새 세이브 단위이므로) |
| 달성 상태 표시 | 이미 달성한 단계는 "달성 완료"로 표시 |
| 게임 내 보상 | 이전 세이브에서 받은 보상은 게임 전체 공유로 그대로 사용 가능 |
| 미달성 단계 | 새 세이브에서 진행도를 새로 추적하여 달성 가능 |
| 보상 중복 지급 | 없음. 이미 달성한 단계의 보상은 다시 지급되지 않음. |

### 8.4 단계 진행과 새 세이브 처리 예시

도전과제 "공중 격파율 S랭크 누적"의 1단계(3회), 2단계(5회), 3단계(10회) 케이스.

| 세이브 1 진행 | 세이브 2 진행 | 보상 처리 |
|---------------|---------------|-----------|
| 1단계 달성 (3회) | - | 1단계 보상 받음, 게임 전체 공유 |
| - | 2단계 진행도 새로 시작 (0/5) | 1단계는 "달성 완료" 표시 |
| - | 2단계 달성 (5회) | 2단계 보상 받음, 게임 전체 공유 |
| 3단계 진행도 새로 시작 (0/10) | - | 1, 2단계는 "달성 완료" 표시 |

이 흐름에서 누적 도전과제의 진행도는 항상 활성 단계만 추적된다.

## 9. 해금 순서

### 9.1 순차 해금 지향

장비/기체 해금은 **한 번에 하나씩 해금되도록 도전과제 배치를 설계**한다. 플레이어가 다음 목표를 명확하게 인지하고 하나씩 달성해나가는 경험을 제공한다.

### 9.2 시스템적 동시 해금 허용

다만, 시스템적으로 한 번에 여러 도전과제를 동시에 달성하는 것 자체를 막지는 않는다. 예를 들어 하나의 미션 클리어로 여러 도전과제 조건을 동시에 충족하면 해당 도전과제들이 모두 달성된다. 이는 시스템 제약이 아닌 도전과제 배치 설계로 순차 해금을 유도하는 방향이다.

## 10. 시스템 간 연동 지점

| 연동 시스템 | 연동 내용 |
|-------------|-----------|
| 로드아웃 시스템 | 해금된 장비 목록이 로드아웃 선택 가능 목록 결정 |
| 기체 시스템 | 기체 해금도 동일 구조 적용 (도전과제 = 게임 전체, 상점 = 세이브 단위) |
| 클리어 평가 시스템 | 평가 결과가 도전과제 조건 판정 데이터로 활용 |
| 동적 캠페인 시스템 | 엔딩 도달 등 캠페인 진행 관련 도전과제 |
| 난이도 시스템 | 난이도 자체를 조건으로 하는 도전과제 (예: Hard 이상 클리어) |
| 슬롯 시너지 시스템 | 시너지 발견 자체가 도전과제 조건이 될 수 있음 (시너지 도감 별도 + 도전과제 시스템 보존 데이터 활용) |

## 12. 확정 사항 요약

| 항목 | 결정 사항 |
|------|-----------|
| 재화 | 단일 통화 1종 |

| 장비 판매/환불/동적 가격 | 모두 없음 |
| 도전과제 해금 대상 | 장비, 기체, 재화 |
| 도전과제 보상 보존 | 게임 전체 공유 |
| 상점 구매 보존 | 세이브 단위 |
| 미채용 조건 | 누적 플레이 횟수, 특정 빌드 강제 |

| 도전과제 단계 | 단일 도전과제가 여러 단계 가능 (1단계 클리어 → 2단계 활성) |
| 보상 양립 | 게임 내 보상 + 트로피 보상 동시 가능 |
| 진행도 추적 | 누적 추적 / 달성 판별 (T/F) 2방식 |
| 진행도 추적 단위 | 세이브 단위 |
| 달성 기록 보존 | 게임 전체 공유 |
| 새 세이브 처리 | 진행도 새로 시작, 이미 달성한 단계는 "달성 완료" 표시, 보상 중복 지급 없음 |
| 해금 순서 | 순차 해금 지향 (배치 설계). 시스템적 동시 해금은 허용. |
