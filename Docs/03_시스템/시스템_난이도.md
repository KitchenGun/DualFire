## 1. 개요

본 문서는 **난이도 시스템**의 세부 설계를 정의한다. 난이도는 미션별로 선택 가능하며, 난이도에 따라 별도의 스테이지 데이터를 사용하여 적 구성, 패턴, 스탯, 정보 제공 수준 등이 변화한다.

---

## 2. 난이도 단계

### 2.1 3단계 구조

| 단계 | 명칭 | 해금 조건 |
|------|------|-----------|
| 1단계 | Normal | 처음부터 해금 |
| 2단계 | Hard | 해당 미션 Normal 클리어 후 해금 |
| 3단계 | Nightmare | 해당 미션 Hard 클리어 후 해금 |

### 2.2 3단계를 채택한 이유

- 2단계(Normal/Hard)는 리플레이 동기가 부족할 수 있다.
- 4단계 이상은 난이도별 스테이지 데이터 제작 공수가 과도하게 증가한다.
- 3단계는 리플레이 깊이와 제작 공수의 균형점이다.

---

## 3. 난이도별 변화 요소

### 3.1 변화 범위

난이도가 올라가면 다음 요소들이 변화할 수 있다.

| 변화 요소 | 설명 |
|-----------|------|
| 적 구성 | 적의 종류, 수량, 배치가 변화 |
| 적 스탯 | 체력, 공격력, 탄속 등 수치 변화 |
| 적 패턴 | 공격 패턴, 이동 패턴 변화 |
| 보스 패턴 | 보스의 공격 패턴, 페이즈 구성 변화 |
| 아이템 드롭 | 드롭 빈도, 배치 변화 |
| 브리핑 정보 | 적 구성 힌트 표시/비표시 |

### 3.2 Nightmare 난이도 차별화 방향

Nightmare 난이도는 Hard 대비 다음 방향으로 차별화된다.

- 적 패턴의 다양화 추가
- 보스 패턴 대폭 변화 (페이즈 구성, 공격 종류 등)
- 적 스탯의 점진적 추가 강화

구체적인 차별화 디자인은 레벨 디자인 단계에서 결정한다. Nightmare는 단순 스탯 인플레가 아니라 게임 메커닉 자체의 변화로 도전감을 제공하는 방향을 지향한다.

### 3.3 난이도별 스테이지 데이터

난이도별 변화는 **별도의 스테이지 데이터**로 관리한다. 같은 미션이라도 난이도에 따라 다른 스테이지 데이터를 로드한다.

이 방식은 동적 캠페인의 스테이지 치환 구조와 동일한 로직을 사용한다. 난이도 치환과 캠페인 치환이 같은 시스템으로 동작하므로 구현 일관성이 유지된다 (시스템_스테이지구조 7절 및 시스템_동적캠페인 6절 참고).

### 3.4 정보 차등

난이도가 올라가면 정보 비대칭이 형성되어 도전감이 증가한다.

| 항목 | Normal | Hard | Nightmare |
|------|--------|------|-----------|
| 적 구성 힌트 | 표시 | 비표시 (안내 메시지) | 비표시 (안내 메시지) |
| 동적 캠페인 연동 메시지 | 표시 | 표시 | 표시 |
| 빌드 유효성 경고 | 작동 | 비작동 | 비작동 |

#### 정보 차등 정책의 일관성

- **적 구성 힌트:** 미션 내부에서 무엇이 나올지에 대한 사전 정보. Hard 이상 비표시로 정보 비대칭 형성.
- **동적 캠페인 연동 메시지:** 플레이어 행동의 결과 피드백. 난이도 무관 항상 표시.
- **빌드 유효성 경고:** 적 구성 힌트 기반 동작. 힌트가 비표시인 상황에서 경고만 동작하면 정보가 간접 누설되므로 함께 비활성화.

세부는 시스템_미션브리핑_v0.2 4절, 코어시스템_로드아웃_v0.3 6절 참고.

## 4. 난이도 선택

### 4.1 미션별 선택

난이도는 **미션별로 선택** 가능하다. 캠페인 단위로 고정하지 않으며, 각 미션 출격 시 난이도를 선택한다.

### 4.2 선택 시점

난이도 선택은 **캠페인 맵의 미션 선택 화면에서** 이루어진다. 미션 노드를 선택하는 동시에 난이도를 함께 선택한다.

전체 출격 플로우:

```
캠페인 맵 → 미션 + 난이도 선택 → 미션 브리핑 → 기체 + 로드아웃 세팅 → 출격
```

### 4.3 미션별 선택을 채택한 이유

- **리플레이 유연성:** 특정 미션만 높은 난이도로 도전하고 싶은 플레이어의 수요를 지원한다.
- **점진적 도전:** 전체 캠페인을 Hard로 시작하는 부담 없이, 자신 있는 미션부터 높은 난이도에 도전할 수 있다.
- **해금 조건 연동:** 장비 해금 도전과제에 "특정 미션을 Hard 이상으로 클리어" 같은 조건을 유연하게 설정할 수 있다.

### 4.4 해금 단위

난이도 해금은 **미션 단위**로 이루어진다. 미션 3을 Normal로 클리어하면 미션 3의 Hard가 해금되는 것이지, 전체 캠페인의 Hard가 해금되는 것이 아니다.

### 4.5 미션 간 독립성

각 미션의 난이도 해금은 다른 미션의 클리어 여부와 무관하다. 예를 들어:

- 미션 4를 Normal로 클리어하지 않은 상태라도, 미션 5의 Normal을 클리어했다면 미션 5의 Hard 도전 가능
- 미션마다 독립적으로 Normal → Hard → Nightmare 순서로 해금됨

플레이어는 자신 있는 미션부터 자유롭게 상위 난이도에 도전할 수 있다.

## 5. 난이도 해금 구조

### 5.1 순차 해금

| 해금 흐름 | 조건 |
|-----------|------|
| Normal → Hard | 해당 미션 Normal 클리어 |
| Hard → Nightmare | 해당 미션 Hard 클리어 |

### 5.2 해금 보존 단위

난이도 해금은 **게임 전체 공유**로 보존된다. 새 세이브 데이터를 시작해도 이미 해금된 난이도는 그대로 사용 가능하다.

이 정책의 의도:
- 즉시 리플레이 방식에서 새 세이브의 의미를 영속 보상으로 보장
- 도전과제 해금(게임 전체) + 시너지 도감(게임 전체) + 난이도 해금(게임 전체)이 일관된 영속 보상 구조 형성
- 한번 도전한 난이도를 새 세이브에서 다시 해금해야 하는 번거로움 방지

### 5.3 순차 해금을 채택한 이유

- Normal을 통해 미션의 기본 구성을 학습한 뒤 Hard에서 변화된 구성에 도전하는 흐름이 자연스럽다.
- 상위 난이도에서는 브리핑 정보가 비표시되므로, Normal에서의 학습 경험이 전제되어야 한다.
- 단계별 성취감을 제공한다.

## 6. 난이도별 보상

### 6.1 재화 차등

높은 난이도에서 미션 클리어 시 **더 많은 재화**를 보수로 지급한다. 구체적인 배율은 밸런싱 단계에서 결정한다.

### 6.2 해금 조건 비완화

높은 난이도에서 플레이해도 **해금 조건이 완화되지 않는다.** 난이도 자체가 해금 조건과 연결될 수 있으므로, 난이도에 따른 조건 완화는 시스템의 일관성을 해친다.

예를 들어 "미션 5를 종합 S랭크로 클리어"라는 도전과제가 있을 때, Hard에서 클리어했다고 A랭크에서 달성으로 처리하지 않는다. S랭크는 S랭크로 달성해야 한다.

### 6.3 난이도 연동 도전과제

난이도 자체를 조건으로 하는 도전과제가 존재할 수 있다.

- "미션 X를 Hard로 클리어" → 특수 장비 해금
- "Nightmare 난이도 엔딩 도달" → 특수 기체 해금

## 7. 분기 미션과 엔딩 미션의 난이도

### 7.1 분기 미션 난이도

동적 캠페인의 분기 미션도 **시스템적으로 Normal/Hard/Nightmare 모두 운영 가능**하다. 다만 컨텐츠 디자인에 따라 일부 분기 미션은 특정 난이도만 존재할 수 있다.

분기 미션의 난이도 차별화 적용 여부는 레벨 디자인 단계에서 결정한다. 시스템 자체는 모든 가능성을 열어둔다.

### 7.2 엔딩 미션 난이도

엔딩 미션은 **별도의 난이도 선택을 두지 않는다.** 데이터적으로는 Normal로 처리된다.

이 정책의 이유:
- 엔딩은 다중 엔딩 구조로 운영되며 (시나리오 기획 참고), 각 엔딩 미션이 분기 누적 조건에 따라 결정됨
- 어떤 엔딩에 도달하는지 자체가 도전 차별화 요소
- 엔딩 미션마다 별도의 Normal/Hard/Nightmare 변형을 만들면 작업량 폭증

분기 누적 조건의 난이도가 곧 엔딩 미션의 도전 난이도가 된다. 까다로운 분기 조건을 충족할수록 더 도전적인 엔딩 미션에 도달하는 식의 자연스러운 그라데이션이 시나리오/레벨 디자인 단계에서 적용된다.

## 8. 난이도와 다른 시스템의 관계

### 8.1 스테이지 데이터 관리

동일 미션의 난이도별 스테이지는 별도 데이터로 관리한다. 스테이지 구조 시스템의 기존 구조를 그대로 사용하며, 미션 로드 시 난이도에 따라 대응하는 스테이지 ID를 선택한다.

### 8.2 동적 캠페인과의 조합

동적 캠페인에 의한 스테이지 치환과 난이도 치환이 동시에 적용될 수 있다. 예를 들어 "미션 4의 Hard 난이도 + 동적 캠페인 변화 버전"은 독립된 스테이지 데이터가 된다.

스테이지 수 예상: 미션 수 × 난이도 3단계 × 캠페인 분기. 모든 조합이 반드시 차등 제작될 필요는 없으며, 변화가 필요한 조합만 별도 데이터로 제작한다.

### 8.3 클리어 평가

클리어 평가 데이터는 **스테이지 ID + 난이도 조합별로 독립 기록**된다 (시스템_클리어평가 6절 참고).

같은 미션이라도:
- Normal 스테이지의 평가 기록
- Hard 스테이지의 평가 기록
- Nightmare 스테이지의 평가 기록

이 모두가 독립적으로 보존되며, 도전과제 추적도 정확하게 이루어진다.

## 9. 시스템 간 연동 지점

| 연동 시스템 | 연동 내용 |
|-------------|-----------|
| 스테이지 구조 | 난이도별 별도 스테이지 데이터. 치환 로직 공유. |
| 미션 브리핑 시스템 | 난이도별 정보 표시/비표시 제어. 적 구성 힌트는 Hard 이상 비표시. 동적 캠페인 메시지는 항상 표시. |
| 로드아웃 시스템 | Hard 이상에서 빌드 유효성 경고 비작동 |
| 동적 캠페인 시스템 | 난이도 × 캠페인 분기 조합. 동일 스테이지 치환 메커니즘. 엔딩 미션은 난이도 선택 없음. |
| 클리어 평가 시스템 | 스테이지 ID + 난이도 조합별 독립 평가 기록 |
| 장비 해금 시스템 | 난이도 연동 도전과제 |
| 보스 페이즈 시스템 | 난이도별 보스 패턴/페이즈 변화 (Nightmare 차별화의 핵심) |
