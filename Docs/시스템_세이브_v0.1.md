## 1. 개요

본 문서는 게임의 **세이브 시스템**을 정의한다. 세이브 시스템은 모든 시스템에 분산되어 있는 데이터 보존 정책을 통합 관리하는 메타 시스템이다.

본 게임은 즉시 리플레이 방식을 채택하므로 다회차 개념이 약하지만, 다양한 분기 탐색과 빌드 실험을 위해 다중 세이브 슬롯을 제공한다. 또한 도전과제, 난이도 해금, 시너지 도감 등 일부 데이터는 게임 전체 공유로 보존하여 새 세이브의 의미를 영속 보상으로 보장한다.

---

## 2. 세이브 슬롯 구조

### 2.1 다중 슬롯 시스템

세이브 슬롯은 **5개 제공**된다. 플레이어는 5개 슬롯 중 하나를 선택하여 캠페인을 진행하거나, 새 세이브로 다른 슬롯에서 별도의 진행을 시작할 수 있다.

### 2.2 5개 슬롯을 채택한 이유

- 단일 슬롯은 분기 탐색과 빌드 실험에 제약이 됨
- 무제한 슬롯은 관리 부담 증가, 의미 없음
- 5개는 다양한 분기 진행/빌드 실험에 충분하면서도 관리 가능한 수

### 2.3 슬롯 운영

| 동작 | 설명 |
|------|------|
| 슬롯 선택 | 게임 시작 시 슬롯 선택 화면에서 5개 슬롯 중 선택 |
| 새 세이브 시작 | 빈 슬롯 또는 기존 슬롯 덮어쓰기 |
| 이어하기 | 사용 중인 슬롯 선택 시 마지막 진행 상태 로드 |
| 슬롯 삭제 | 슬롯의 데이터를 모두 삭제하고 빈 슬롯으로 복귀 |
| 슬롯 복사 | 미지원 (필요시 추후 검토) |

### 2.4 슬롯 정보 표시

슬롯 선택 화면에서 각 슬롯에 다음 정보를 표시한다.

| 표시 정보 | 설명 |
|-----------|------|
| 슬롯 번호 | 1~5 |
| 진행 상태 | 빈 슬롯 / 진행 중 / 엔딩 도달 |
| 캠페인 진행도 | 클리어한 미션 수, 도달한 막 등 |
| 마지막 플레이 시각 | 최근 저장 시각 |
| 플레이 시간 | 누적 플레이 시간 |

UI 디테일은 UI 시스템 기획에서 정의한다.

## 3. 데이터 보존 단위 매트릭스

### 3.1 통합 보존 단위 표

모든 시스템의 데이터 보존 단위를 통합 정리한다. 각 데이터는 **세이브 슬롯 단위** 또는 **게임 전체 공유** 중 하나로 보존된다.

#### 3.1.1 세이브 슬롯 단위 보존 데이터

각 세이브 슬롯이 독립적으로 가지는 데이터.

| 데이터 | 출처 시스템 |
|--------|-------------|
| 캠페인 진행 상태 (해금된 미션, 클리어 여부, 분기 미션 해금 상태) | 동적 캠페인 |
| 상점 구매 장비 보유 목록 | 장비 해금 |
| 상점 구매 기체 보유 목록 | 기체 / 장비 해금 |
| 미션 클리어 보수로 획득한 재화 잔액 | 장비 해금 |
| 로드아웃 프리셋 | 로드아웃 |
| 평가 데이터 (전체 플레이 기록) | 클리어 평가 |
| 도전과제 진행도 (현재 카운트) | 장비 해금 |
| 누적 플레이 시간 | (본 시스템) |
| 마지막 진행 위치 | (본 시스템) |

#### 3.1.2 게임 전체 공유 보존 데이터

모든 세이브 슬롯이 공유하는 데이터.

| 데이터 | 출처 시스템 |
|--------|-------------|
| 도전과제 달성 기록 | 장비 해금 |
| 도전과제 해금으로 획득한 장비 보유 | 장비 해금 |
| 도전과제 해금으로 획득한 기체 보유 | 기체 / 장비 해금 |
| 도전과제 해금으로 획득한 재화 잔액 | 장비 해금 |
| 난이도 해금 상태 (미션별 Hard/Nightmare 해금) | 난이도 |
| 시너지 도감 (발견한 시너지 목록) | 슬롯 시너지 |
| 게임 옵션 (입력, 화면, 사운드 등) | (본 시스템) |

### 3.2 보존 단위 차별화 원칙

| 원칙 | 적용 |
|------|------|
| 캠페인 진행 자체는 세이브 단위 | 새 세이브에서 처음부터 시작 가능 |
| 플레이어 숙련의 결과는 게임 전체 공유 | 도전과제 달성, 난이도 해금, 시너지 발견 |
| 게임 내 자원 중 도전과제 보상은 게임 전체 공유 | 장비, 기체, 재화 모두 해당 |
| 일반 자원(상점 구매, 미션 보수)은 세이브 단위 | 캠페인 진행감 유지 |

## 4. 새 세이브 초기 상태

새 세이브를 시작할 때 세이브 슬롯의 초기 상태는 다음과 같다.

| 항목 | 초기값 |
|------|--------|
| 캠페인 진행 | 미션 1만 해금. 기본 루트 진행 가능. |
| 해금된 난이도 (세이브 슬롯 기준) | 미션 1의 Normal만 (단, 게임 전체 공유 해금이 우선 적용) |
| 보유 기체 | 1대 (기본 기체) |
| 보유 장비 | 각 슬롯에 사용 가능한 최소한의 장비 (기본 무기 1, 특수무장 1, 슈퍼웨폰 1, 보호막 1) |
| 재화 | 0 |
| 프리셋 | 없음 |
| 평가 데이터 | 비어있음 |
| 도전과제 진행도 | 모든 도전과제 0/n으로 초기화 |
| 플레이 시간 | 0 |

### 4.1 게임 전체 공유 데이터의 영향

새 세이브를 시작해도 게임 전체 공유 데이터는 그대로 유지되어 새 세이브에 즉시 적용된다.

| 영역 | 영향 |
|------|------|
| 도전과제 해금 장비/기체 | 새 세이브에서도 즉시 사용 가능 |
| 도전과제 해금 재화 | 새 세이브의 재화 잔액에 포함 (단, 재화는 한 번만 지급되므로 신규 새 세이브에는 적용 안 됨 — 이미 받은 보상이므로) |
| 난이도 해금 | 새 세이브에서도 동일하게 해금 상태 유지 |
| 시너지 도감 | 새 세이브에서도 발견 정보 유지 |

#### 4.1.1 재화의 처리 명확화

도전과제 보상으로 받은 재화는 **재화를 받은 시점에 한 번만** 지급되므로, 새 세이브 시작 시 자동으로 재화 잔액에 추가되지 않는다. 게임 전체 공유로 보존되는 것은 "이 도전과제로 받은 재화의 누적 기록"이지, 매번 새 세이브에 재화가 자동 지급되는 구조가 아니다.

새 세이브를 시작하면 재화는 0에서 시작한다. 다만 도전과제 해금 장비/기체는 이미 보유 상태로 시작하므로, 새 세이브 초반의 빌드 다양성 측면에서 영구 보상이 작동한다.

### 4.2 새 세이브 시작 흐름

1. 슬롯 선택 화면에서 빈 슬롯 또는 덮어쓸 슬롯 선택
2. (덮어쓰기인 경우) 확인 안내
3. 새 세이브 데이터 생성 (위 초기 상태로)
4. 게임 전체 공유 데이터 자동 적용
5. 캠페인 맵 진입

## 5. 자동 저장

### 5.1 자동 저장 시점

다음 시점에 자동으로 저장된다.

| 시점 | 저장 대상 |
|------|-----------|
| 미션 클리어 직후 | 캠페인 진행, 평가 데이터, 재화 (보수), 도전과제 진행도 |
| 상점 거래 직후 | 보유 장비/기체, 재화 잔액 |
| 옵션 변경 직후 | 게임 옵션 (게임 전체 공유) |
| 도전과제 달성 시 | 달성 기록 (게임 전체 공유), 보상 지급 |
| 난이도 해금 시 | 난이도 해금 상태 (게임 전체 공유) |
| 시너지 발견 시 | 시너지 도감 (게임 전체 공유) |
| 분기 미션 해금 시 | 캠페인 진행 |

### 5.2 수동 저장 미지원

수동 저장은 지원하지 않는다. 자동 저장 시점이 충분히 빈번하므로 수동 저장의 필요성이 낮다.

### 5.3 미션 진행 중 저장 미지원

미션 진행 중에는 저장이 이루어지지 않는다. 미션은 한 번 출격하면 클리어 또는 실패까지 완주해야 하며, 중간 저장 후 종료 같은 동작은 지원하지 않는다.

## 6. 데이터 저장 구조

### 6.1 파일 구조

| 파일 | 내용 | 보존 단위 |
|------|------|-----------|
| 세이브 슬롯 1~5 | 각 슬롯의 캠페인 진행, 보유 장비, 프리셋 등 | 슬롯 단위 |
| 게임 전체 공유 파일 | 도전과제 달성 기록, 난이도 해금, 시너지 도감, 옵션 등 | 게임 전체 |

5개의 세이브 슬롯 파일과 1개의 게임 전체 공유 파일이 별도로 관리된다. 모든 세이브 슬롯이 게임 전체 공유 파일을 참조한다.

### 6.2 저장 위치

저장 파일의 위치와 형식은 프로그래머 영역에서 결정한다. 본 문서에서는 논리적 구조만 정의한다.

## 7. 시스템 간 연동 지점

| 연동 시스템 | 연동 내용 |
|-------------|-----------|
| 동적 캠페인 시스템 | 캠페인 진행 상태 보존, 새 세이브 시 미션 1 해금 상태로 시작 |
| 기체 시스템 | 보유 기체 보존 (상점=세이브, 도전과제=공유) |
| 로드아웃 시스템 | 보유 장비 보존, 프리셋 보존 (세이브 단위) |
| 장비 해금 시스템 | 도전과제 진행도(세이브) + 달성 기록(공유) + 보상(공유) 분리 보존 |
| 클리어 평가 시스템 | 모든 플레이 기록 보존 (세이브 단위) |
| 난이도 시스템 | 난이도 해금 상태 보존 (게임 전체 공유) |
| 슬롯 시너지 시스템 | 시너지 도감 보존 (게임 전체 공유) |

## 9. 확정 사항 요약

| 항목 | 결정 사항 |
|------|-----------|
| 세이브 슬롯 수 | 5개 |
| 슬롯 운영 | 새 세이브, 이어하기, 덮어쓰기, 삭제 지원. 슬롯 복사는 미지원. |

| 게임 전체 공유 데이터 | 도전과제 달성/보상, 난이도 해금, 시너지 도감, 게임 옵션 |
| 자동 저장 시점 | 미션 클리어, 상점 거래, 옵션 변경, 도전과제 달성, 난이도 해금, 시너지 발견, 분기 해금 |
| 수동 저장 | 미지원 |
| 미션 중 저장 | 미지원 |
| 파일 구조 | 세이브 슬롯 5개 파일 + 게임 전체 공유 1개 파일 |
| 저장 위치/형식 | 프로그래머 영역에서 결정 |
