## 1. 개요

본 문서는 플레이어 기체의 **기동 시스템**을 정의한다. 이동 속도 모드, 히트박스, 이동 범위, 입력 방식 등 플레이어 기체의 조작과 관련된 기본 스펙을 다룬다.

본 시스템은 모든 기체에 공통으로 적용되며, 기체별 기본 기동 차이는 두지 않는다. 단, 슈퍼웨폰 효과, 기체 특성, 슬롯 시너지 등에서 일시적으로 기동에 영향을 줄 수 있다 (6장 참고).

## 2. 이동 속도 모드

### 2.1 2단계 속도 지원

플레이어 기체는 통상 속도와 저속 모드의 2가지 이동 속도를 가진다.

| 모드 | 용도 |
|------|------|
| 통상 속도 | 기본 이동. 일반적인 전투 상황에서 사용. |
| 저속 모드 | 정밀 이동. 고난도 구간에서 정밀 회피 시 사용. |

### 2.2 2단계를 채택한 이유

이 게임은 탄막 슈팅이 아닌 피탄 허용형 설계이므로, 정밀 회피 단계를 다단계로 나눌 필요가 적다. 2단계가 입력 복잡도와 활용도의 균형점이다.

### 2.3 저속 모드 속도 비율

저속 모드의 이동 속도는 통상 속도 대비 **데이터로 설정 가능**하다. 구체적인 비율은 프로토타입에서 결정한다.

### 2.4 저속 모드 진입 방식

- **기본 설정:** 홀드 방식. 지정 버튼을 누르고 있는 동안 저속 모드 유지, 떼면 통상 속도로 복귀
- **옵션 설정:** 토글 방식으로 변경 가능. 버튼을 한 번 누르면 저속, 다시 누르면 통상으로 전환

홀드/토글 전환은 게임 옵션에서 플레이어가 선택할 수 있다.

**저속 모드는 이동 속도만 변경한다.** 발사·특수무장·슈퍼웨폰 사용 등 모든 행동은 통상 속도와 동일하게 가능하며, 어떤 행동 제약도 없다.

**토글 상태의 리셋:** 토글 방식 사용 시, 미션 시작·사망·리스폰 시점에 저속 토글 상태를 통상 속도로 리셋한다 — 리스폰 직후 의도치 않은 저속 상태로 복귀하는 위험 방지. 홀드 방식은 버튼 물리 상태를 그대로 따르므로 별도 리셋이 없다.

### 2.5 저속 모드 시 시각적 피드백

저속 모드 진입 시 **히트박스를 표시하지 않는다.** 이 게임은 탄막 슈팅이 아닌 피탄 허용형 설계이므로, 히트박스 표시가 회피를 지나치게 쉽게 만들어 보호막 관리의 의미가 희석된다. 저속 모드 진입 여부는 기체 이펙트 변화(엔진 출력 변화 등) 정도의 경미한 시각적 피드백으로 처리한다.

## 3. 이동 방향 및 처리

### 3.1 입력 장치별 이동 방향

이동 방향의 해석은 입력 장치에 따라 다르다.

- **키보드: 8방향(상하좌우 + 대각선)** — 종스크롤 슈팅의 표준 방식
- **게임패드: 방향은 연속(자유 각도), 크기만 디지털화** — 스틱 각도를 그대로 사용하며, 데드존 통과 시 해당 각도로 최대 속도 이동 (3.4)

패드 방향을 8방향으로 양자화하지 않는 이유: 스틱에서 방향이 툭툭 꺾이는 조작감을 피하고 아날로그의 방향 표현력은 유지하되, 속도는 통상/저속 2단계 철학을 그대로 지킨다. 키보드와 패드는 이동 속도 크기 체계가 동일하므로 기본 이동속도 면의 차이는 없다. 다만 방향 해상도 차이(8방향 vs 연속 방향)가 회피·경로 선택에 미치는 영향은 프로토타입에서 검증한다 [검증 — 8방향 양자화와 조작감 비교]

### 3.2 즉각 반응

키 입력 즉시 최대 속도로 이동한다. 가속 또는 감속 곡선은 두지 않는다. 이는 슈팅 게임의 정밀 조작감을 위한 표준 방식이다.

### 3.3 키보드 대각선 이동 속도 보정

키보드의 대각 이동 시 **속도 보정(벡터 정규화)을 적용**한다. 보정 없이 두 축을 합산하면 대각선이 다른 방향보다 빠르게 이동하는 문제가 발생한다. 모든 방향에서 동일한 이동 속도를 유지한다. 게임패드는 3.4에서 방향 벡터를 정규화하므로 같은 문제가 별도로 발생하지 않는다.

### 3.4 입력 방향의 해석

**아날로그 스틱 — 방향 연속, 크기 디지털화:** 스틱 입력 크기가 데드존 이하면 이동 입력 0. 데드존을 통과하면 **방향 벡터를 정규화하여 그 각도로 현재 모드(통상/저속)의 최대 속도**로 이동한다. 기울기에 비례한 중간 속도는 두지 않는다.

- 정밀 이동은 저속 모드가 전담하는 축이다 — 비례 속도를 두면 역할이 중복된다
- 속도의 즉각 반응 원칙(3.2)과 일관된다
- 데드존은 **방사형(스틱 입력 크기 기준)**으로 처리한다 — 축별 데드존은 대각 방향을 왜곡하므로 사용하지 않는다

**반대 방향 동시 입력 (키보드):** 같은 축의 반대 방향이 동시에 입력되면 **해당 축은 상쇄되어 정지**한다. 축은 독립 처리한다 (예: 좌+우+상 동시 입력 = 위로 이동).

### 3.5 이동과 외형·발사 방향의 관계

- 플레이어의 기본 전방과 기본 무기 발사 방향은 **항상 화면 위쪽**이다 — 이동 방향은 발사 방향을 바꾸지 않는다
- 좌우 이동 시 기체 외형이 시각적으로 기울 수 있으나(롤링 연출), **외형 기울기는 히트박스·발사구·클램프에 영향을 주지 않는다** (4.4의 공통 앵커 구조)
- 이동 방향으로 사격하는 특수 무기가 필요하면 해당 무기 데이터의 예외로 처리한다

## 4. 히트박스

### 4.1 크기 방향성

히트박스 크기는 프로토타입에서 최종 결정하되, 다음 방향성을 따른다.

- 기체 모델보다 작게 설정 (모델 크기 = 히트박스가 아님)
- 탄막 슈팅 게임보다는 크게 설정 (극단적으로 작은 히트박스 미채용)
- 피탄 허용형 설계 의도와 일관되게, 회피 자체는 가능하되 완전 회피가 아닌 보호막 관리가 핵심이 되도록

### 4.2 고정 크기

히트박스 크기는 **이동 속도 모드와 무관하게 고정**이다. 통상 속도에서도 저속 모드에서도 히트박스 크기는 동일하다.

고정 크기를 채택한 이유는, 히트박스가 동적으로 바뀌면 피격 판정이 직관적이지 않게 되기 때문이다. 플레이어가 고속과 저속을 넘나들며 전투하는 상황에서 히트박스까지 변하면 "지금 맞을 건지 안 맞을 건지" 판단이 불안정해진다.

### 4.3 전 기체 동일

히트박스 크기는 **모든 기체에서 동일**하다. 기체별 기동 차이를 두지 않는 원칙의 일환이다.

### 4.4 위치

히트박스는 기체 모델 메시의 피벗이나 렌더링 중심이 아니라, **모든 기체가 공유하는 공통 기준점(히트박스 앵커)**에 배치한다.

- 기체 프리팹은 공통 구조를 가진다: **이동 위치 기준점 / 히트박스 앵커 / 발사구 앵커 / 외형부**(기울기·애니메이션 적용 대상)
- 기체마다 메시 피벗·시각적 무게중심이 달라도 판정 중심은 전 기체 동일 위치로 통일된다
- **외형의 기울기·애니메이션은 히트박스의 위치·회전에 영향을 주지 않는다** — 외형부만 회전한다
- 히트박스 크기와 앵커 오프셋의 최종 값은 프로토타입에서 플레이 감각으로 확정한다 [검증]
- 이 히트박스가 판정 분리 시스템의 피격 콜리전이며, 램 overlap 판정에도 동일하게 사용된다

## 5. 이동 범위

### 5.1 플레이필드 전체 이동

플레이어 기체는 **플레이필드 내부 전체 범위에서 자유롭게 이동**할 수 있다. 하단 제한 같은 이동 범위 제약은 두지 않는다. 플레이필드 경계 밖(좌우 월드·연출 영역 포함)으로는 이동 불가. (플레이필드 정의는 좌표계·카메라·화면 규격 문서)

### 5.2 플레이필드 경계 처리

플레이어가 플레이필드 경계에 도달하면 보이지 않는 벽처럼 작동하여 그 너머로 이동할 수 없다. 입력은 받아들이되 위치는 경계에서 고정된다.

**클램프 기준 — 전 기체 공통의 정적 이동 경계 바운드:** 클램프는 모든 기체가 공유하는 **고정 크기의 정적 바운드**를 기준으로 한다. 실시간 렌더링 모델 바운드나 기울기 애니메이션의 변화는 클램프 계산에 반영하지 않는다.

- 기체 아트는 이 공통 바운드 안에 들어오도록 제작·스케일을 조정한다 — **최대 롤링·모든 정상 애니메이션 상태를 포함한 시각적 외곽**이 바운드 안에 유지되어야 한다 (아트 제작 규격으로 보장)
- 런타임 모델 바운드를 쓰지 않는 이유: 기체별 외형 크기가 다르면 유효 이동 범위가 달라져 **전 기체 동일 기동 원칙이 깨지고**, 기울기·애니메이션으로 바운드가 변하면 경계에서 위치가 흔들린다
- 좌우 경계는 **좌우 월드·연출 영역**(월드 배경이 이어지는 시각 공간, 판정 없음)과 접하므로, 기체가 플레이필드를 시각적으로 벗어나지 않는 것이 판정 공간 인지에 중요하다
- 그림자와 이펙트는 클램프 대상이 아니다 (그림자는 고도 오프셋 표현상 경계 밖 표시 허용)

### 5.3 스크롤과 플레이어 이동의 관계

자동 스크롤은 플레이어의 이동과 **완전히 독립적**으로 동작한다.

- 플레이어가 위로 이동해도 스크롤이 빨라지지 않음
- 플레이어가 아래로 이동해도 스크롤이 느려지지 않음
- 플레이어가 플레이필드 어느 위치에 있더라도 스크롤은 정상 진행
- 스크롤 속도는 스테이지 데이터에 의해서만 결정됨

플레이어는 자동 스크롤되는 화면 내에서 자유롭게 이동하며 전투한다. 스크롤은 전장이 흘러가는 흐름이고, 플레이어는 그 안에서 움직이는 별개의 대상이다.

### 5.4 미션 시작·리스폰 위치와 진입

- **시작·리스폰 위치 = 플레이어 시작 앵커.** 시작 앵커는 플레이필드 하단 중앙의 **최저 합법 이동 위치**다 — 정규화 원점 (0, 0) 자체가 아니라, 공통 클램프 바운드의 반높이를 반영해 기체가 온전히 플레이필드 안에 들어오는 위치 (기체 중심을 Y=0에 두면 바운드 절반이 필드 밖으로 나간다). 리스폰 위치(생존 시스템)와 동일 지점으로 통일하여 진입 연출 자산을 공유한다
- 미션 시작과 리스폰 모두 **플레이필드 밖 하단에서 시작 앵커로 날아 들어오는 짧은 진입 연출**을 거친다. 진입 연출 중에는 조작이 잠긴다 (8.4)
- **미션 시작 시 무적은 없다** — 시작 직후 교전이 없는 스테이지 구성을 전제하며, 생존 시스템의 미션 시작 초기화(무적 출처 전부 비활성)와 정합
- 리스폰 시에는 생존 시스템의 리스폰 무적(3초)이 적용된다. 무적 타이머의 시작 시점은 8.4 참고

**진입 연출 중 상태 (시작·리스폰 공통):** 진입은 정상 이동과 별개의 **스크립트 이동**이다.

- 플레이어 입력 이동 비활성, 정상 클램프 미적용 (플레이필드 밖 → 안 이동이므로), 스크립트 경로 사용
- **피격 콜리전 비활성** — 적의 타겟 후보에서 제외, 램 overlap 판정 불가, 아이템 획득 불가
- 연출 종료 시 순서 (리스폰): 시작 위치 안착 → **리스폰 무적 출처 활성화** → 피격 콜리전 활성화 → 적 타겟 후보 등록 → 조작 잠금 해제. **첫 피격 가능 프레임에는 이미 리스폰 무적이 활성 상태여야 한다** — 콜리전 활성화와 무적 시작 사이의 틈 방지 (전체 전환을 원자적으로 처리)
- 연출 종료 시 순서 (미션 시작): 시작 위치 안착 → 피격 콜리전 활성화 → 적 타겟 후보 등록 → 조작 잠금 해제 (별도 무적 없음)

"시작 시 무적 없음"은 조작 가능 이후의 상태를 말한다 — 진입 연출 중에는 콜리전 자체가 비활성이므로 피격되지 않는다.

### 5.5 월드 오브젝트와의 물리 충돌 없음

플레이어 이동은 **플레이필드 경계 외의 어떤 대상과도 물리적 blocking 충돌을 발생시키지 않는다.**

- 적 본체와의 접촉은 위치를 밀어내지 않는 overlap 램 판정으로 처리한다 (판정 분리 시스템 6장)
- 배경·지형·지상 구조물(건물, 절벽 등)은 시각 요소이며 이동을 막지 않는다 — 플레이어가 공중에 있다는 설정과 일관된다
- 장애물형 컨텐츠가 필요해지면 그때 별도 시스템으로 연다

## 6. 기동 스탯과 기체의 관계

### 6.1 전 기체 동일 기본 기동

기본 기동 스탯(이동속도, 저속 모드 속도, 히트박스 크기)은 **모든 기체에서 동일**하다. 기체별 기본 기동 차이를 두지 않는다.

### 6.2 전 기체 동일 기동을 채택한 이유

- **레벨 디자인 일관성:** 기체마다 이동속도가 다르면 같은 스테이지의 난이도가 기체에 따라 달라진다. 모든 기체에서 동일한 레벨 경험을 제공하기 위해 기동을 통일한다.
- **차별화 축 집중:** 기체의 차별점은 체력 총량과 기체 특성에 집중한다. 이를 통해 기체 선택은 "어떤 스탯과 패시브 효과를 가져갈 것인가"의 판단이 되며, 조작감 차이에 의한 불균형을 방지한다.

### 6.3 일시적 기동 영향 가능성

기본 기동은 전 기체 동일이지만, 다음 시스템들이 **일시적으로 기동에 영향**을 줄 수 있다.

- 슈퍼웨폰 효과: 일시적 이동속도 증가, 무적 대시 등
- 기체 특성: 특정 조건 충족 시 기동 보정
- 슬롯 시너지: 드론 활성화로 인한 간접적 영향

이러한 일시적 영향은 각 시스템에서 정의하며, 기본 기동 자체를 변경하지 않는다.

### 6.4 이동속도 보정 계산

- 원시 통상 속도 = (기본 이동 속도 + 가산 보정 합) × 곱 보정 곱
- **최종 통상 속도 = 원시 통상 속도에 통상 속도 하한·상한 클램프 적용** (값은 데이터)
- **최종 저속 속도 = 최종 통상 속도 × 저속 비율** — 클램프가 끝난 최종 통상 속도에 비율을 곱한다. 저속에 통상과 같은 하한을 공용 적용하면 실효 저속 비율이 왜곡되므로(예: 통상 100·비율 0.3·공용 하한 50이면 실제 비율 0.5), 저속에 별도 제한이 필요하면 저속 전용 하한·상한 값을 따로 둔다
- 복수 효과의 중첩 순서, 이동 불가 상태 등 세부는 전투 처리 흐름 문서에서 확정한다. 프로토타입에는 기동 보정 효과를 넣지 않는다

## 7. 특수 기동

### 7.1 별도 특수 기동 미채용

긴급 회피, 대시, 배럴롤 같은 별도의 특수 기동 시스템은 두지 않는다.

### 7.2 슈퍼웨폰 효과로 흡수

특수 기동에 해당하는 기능(긴급 회피, 무적 돌파 등)은 **슈퍼웨폰의 효과 데이터로 구현**한다. 이를 통해 긴급 회피 능력 자체가 로드아웃 선택의 대상이 되며, 별도의 시스템을 추가하지 않고 기존 로드아웃 프레임워크 안에서 처리한다.

슈퍼웨폰 효과 사양은 **슈퍼웨폰 시스템 세부 기획**에서 다룬다.

## 8. 입력 방식

### 8.1 지원 입력 장치

- **키보드:** 기본 지원
- **게임패드:** 기본 지원

두 입력 장치 모두 기본 지원한다. **키보드는 자유 리매핑, 게임패드는 입력 프리셋 변경**을 지원하며, 세부 정책은 기반 입력 시스템 문서를 따른다.

### 8.2 입력 장치 우선순위 및 자동 전환

입력 장치 우선순위·장치 변경 감지·자동 일시정지·키 리매핑 정책의 **단일 출처는 기반 입력 시스템 문서**다. 본 문서는 이동 입력값을 플레이어 이동으로 해석하는 규칙(3장)과 조작 잠금 시의 처리(8.4)만 정의한다.

참조 요약: 게임 시작 시 패드 연결 여부로 초기 활성 장치 결정, 메뉴 중에는 즉시 전환, 인게임 중에는 다른 장치의 의미 있는 입력 시 자동 일시정지 + 메뉴 확인을 통한 전환. 전환 감지는 버튼 또는 장치 전환 축 임계값(이동 데드존과 별개) 초과 입력만 — 스틱 드리프트 오발 방지. 세부는 기반 입력 문서, 인게임 메뉴 사양은 UI 기획 소관.

### 8.3 게임패드 데드존 설정

게임패드 사용 시 아날로그 스틱의 **데드존을 데이터로 설정 가능**하다. 옵션에서 플레이어가 직접 조정할 수 있다 (기반 입력 문서 준수).

데드존 처리는 3.4의 방사형 방식을 따른다: 입력 크기 ≤ 데드존 → 이동 입력 0 / 초과 → 방향 정규화 + 현재 모드 최대 속도.

### 8.4 조작 잠금 구간

본 문서가 정의하는 **기본 전체 게임플레이 잠금 구간**은 다음 3종이다.

| 구간 | 잠금 범위 | 해제 시점 |
|------|-----------|-----------|
| 미션 시작 진입 연출 | 전체 게임플레이 행동 | 연출 종료 |
| 사망 ~ 리스폰 진입 연출 | 전체 게임플레이 행동 | 리스폰 진입 연출 종료 |
| 일시정지 | 게임플레이 행동 (메뉴 조작만 유효) | 게임 재개 |

**잠금 범위의 정의:** "전체 게임플레이 행동" = 이동·기본 무기·특수무장·슈퍼웨폰·저속 모드 등 인게임 행동. **일시정지·옵션 호출·접근성 관련 시스템 입력은 전체 게임플레이 잠금 중에도 항상 유효하다** (기반 입력 문서의 "일시정지는 어떤 처리 중에도 즉시 반응" 원칙 준수).

**부분 조작 제한:** 보스 등장·페이즈 전환 연출, 시네마틱, 슈퍼웨폰 효과(사용 중 이동 불가/공격 불가), 스크립트 이동(긴급 대시류) 등 외부 시스템은 **필요한 행동 범위에 한해 부분 잠금을 요청**할 수 있다 — 이동만 잠금 / 공격만 잠금 / 특정 무장만 잠금 / 입력 이동의 스크립트 이동 대체 / 메뉴 입력만 허용. 각 요청의 발동 조건은 해당 시스템 문서가 정의하고, 본 시스템은 잠금 상태의 조합을 수용하는 구조를 제공한다. (전체 잠금 3종 "한정"은 기본 발생 구간의 한정이며, 외부 요청을 배제하지 않는다)

**잠금의 출처별 독립 관리:**

- 조작 잠금은 **잠금 출처별로 독립 관리**한다. 각 요청은 출처 식별과 잠금 범위를 가진다
- 한 출처는 **자신이 요청한 잠금만 해제**할 수 있다
- 같은 행동에 하나 이상의 잠금 출처가 남아 있으면 해당 행동은 계속 잠긴다 (예: 보스 전환 연출과 슈퍼웨폰 효과가 모두 이동을 잠근 상태에서 슈퍼웨폰이 종료되어도, 보스 연출의 이동 잠금이 남아 있으므로 이동 불가 유지)
- 전체 잠금이 해제되어도 별도의 부분 잠금은 유지된다

**잠금 해제 시 입력 처리 — 해제 상황별 분리:**

| 해제 상황 | 처리 |
|-----------|------|
| 미션 시작 진입 종료 | **지속 입력**(이동축·기본 무기 홀드·저속 홀드)은 즉시 반영 (다시 누를 필요 없음). **순간 발동 액션**(특수무장·슈퍼웨폰)은 자동 실행하지 않음 — 버튼 해제 후 재입력 필요 |
| 리스폰 진입 종료 | 위와 동일 — 지속 입력 즉시 반영, 순간 액션은 재입력 필요 (리스폰 직후 의도치 않은 슈퍼웨폰 소모 방지) |
| 일시정지 메뉴 종료 | **메뉴 조작에 사용된 입력을 게임플레이로 전달하지 않는다** — 이동축은 중립 복귀, 액션 버튼은 해제 후 재입력되어야 유효 (재개 확인 버튼이 게임 액션 키와 겹쳐 오발되는 사고 방지) |
| 입력 장치 전환 메뉴 종료 | 최초 전환 입력 소비, 새 장치 입력 중립화 후 허용 |
| 시네마틱 종료 | 연출별 설정 가능 (기본 즉시 반영) |

- 입력 버퍼를 지원하는 무장이 있다면 순간 액션의 발동은 해당 공격 시스템의 별도 규칙을 따른다
- **리스폰 무적은 진입 연출 종료 전환에서 콜리전 활성화보다 먼저 켜지며, 타이머는 이 시점(조작 가능 시점과 동일 프레임)부터 카운트한다** — 진입 연출이 무적 시간을 소모하지 않으면서, 첫 피격 가능 프레임부터 무적이 보장된다 (생존 시스템 연동, 5.4 순서 참고)
- 저속 토글 상태 리셋은 2.4 참고

## 10. UI 영역

레이아웃·화면 구성은 UI 기획 문서 소관이다. 본 시스템이 UI에 요구하는 계약은 다음과 같다.

- 저속 모드 상태를 경미한 시각 피드백(엔진 이펙트 변화 등)으로 표시한다 — 히트박스는 표시하지 않는다 (2.5)
- 진입 연출 구간과 조작 가능 시점을 명확히 표현한다 (생존 시스템의 UI 계약과 공유)
- 데드존·홀드/토글 설정은 옵션 화면에서 제공한다 (UI 기획 6호)
- 입력 장치 전환 시 자동 일시정지는 인게임 메뉴로 표현한다

| 활성 장치 | 시작 시 패드 연결 여부로 결정. 인게임 전환은 일시정지+확인, 메뉴는 즉시 (기반 입력 문서 준수) |
| 게임패드 데드존 | 옵션에서 데이터로 설정 |
| 아날로그 해석 | 방향은 연속(자유 각도), 크기만 디지털화 — 방사형 데드존 통과 시 해당 각도로 최대 속도. 키보드는 8방향 |
| 반대 방향 동시 입력 | 해당 축 상쇄(정지), 축 독립 처리 |
| 저속 토글 리셋 | 미션 시작·사망·리스폰 시 통상 복귀. 저속 중 행동 제약 없음 |
| 히트박스 위치 | 전 기체 공통 히트박스 앵커 기준 (메시 피벗 무관). 외형 기울기 무영향. 크기·오프셋은 프로토 확정 |
| 화면 클램프 | 전 기체 공통 정적 이동 경계 바운드 (런타임 바운드·기울기 무반영). 아트는 바운드 규격에 맞춰 제작 |
| 시작·리스폰 진입 | 플레이어 시작 앵커(하단 중앙 최저 합법 위치)로 스크립트 진입 — 진입 중 피격·타겟팅·램·아이템 비활성. 리스폰 종료: 안착→**무적 활성**→콜리전 활성→타겟 등록→잠금 해제 / 시작 종료: 안착→콜리전 활성→타겟 등록→잠금 해제 |
| 조작 잠금 | 기본 전체 게임플레이 잠금 3종 (시스템 입력은 항상 유효) + 부분 잠금은 출처별 독립 관리 (자기 잠금만 해제, 잔존 출처 있으면 유지). 해제 처리 분리: 시작·리스폰 = 지속 입력만 즉시 반영 (순간 액션은 재입력) / 메뉴 종료 = 입력 중립화 |
| 속도 보정 계산 | (기본+가산)×곱 보정. 저속 비율은 최종 통상 속도에 마지막 곱. 하한·상한 데이터 |
| 월드 충돌 | 플레이필드 경계 외 blocking 없음. 램은 overlap, 지형·구조물은 시각 요소 |
| 발사 방향 | 항상 화면 위. 이동·외형 기울기가 발사 방향·히트박스에 무영향 |
| 입력 장치 정책 | 단일 출처 = 기반 입력 문서. 본 문서는 이동 해석과 잠금 처리만 |

## 12. 프로토타입 검증 항목

| 항목 | 검증 내용 |
|------|-----------|
| 통상·저속 속도 값 | 통상 이동 속도와 저속 배율의 조작감 |
| 히트박스 크기·중심 | 플레이 감각 기준 최종 값 (피탄 허용형 의도 유지) |
| 진입 연출 길이 | 시작·리스폰 진입 연출이 흐름을 끊지 않는 길이 |
| 데드존 기본값 | 표준 패드 기준 기본 방사형 데드존 |
| 패드 방향 해석 | 연속 방향+크기 디지털화의 조작감 확인 (8방향 양자화와 비교). 스틱을 조금 기울여도 최대 속도인 방식이 지나치게 민감하지 않은지 |
| 특수무장 동시 입력 | 이동·기본 사격·저속을 유지한 채 특수무장 두 키를 안정적으로 동시 입력 가능한지 |
| 장치 전환 임계값 | 스틱 드리프트로 자동 일시정지가 발생하지 않는지 |
| 일시정지 해제 입력 | 재개 확인 입력이 이동·공격·슈퍼웨폰으로 전달되지 않는지 |
| 공통 클램프 바운드 | 외형 크기가 다른 기체들의 실제 이동 가능 영역이 동일한지 |
| 진입 중 판정 | 진입 연출 중 피격·램·타겟팅·아이템 획득이 발생하지 않는지 |
